# 自動微分

<!--en:c6fa9d57-->
:numref:`sec_calculus` では、2 つのパラメータをもつ直線モデルの勾配 $\nabla_{\mathbf{w}} L = \mathbf{X}^\top (2\mathbf{r}) = (2, 4)$ を手計算で容易に導出できたが、数十の層と数十億個のパラメータにわたって手計算で導出するのは絶望的である。現代の深層学習フレームワークは、この計算を*自動微分*（automatic differentiation、*autograd*）によって自動化する。プログラムがスカラーの損失を評価する際、フレームワークは基本演算をトレースして*計算グラフ*（computational graph）を構築し、そのグラフを逆向きにたどることで（*誤差逆伝播法*、backpropagation）、連鎖律（chain rule）を機械的に適用する。驚くべきことに、モデルのパラメータが 2 個であっても 10 億個であっても、1 回の逆方向スイープだけで*すべて*のパラメータに関する厳密な勾配を、順伝播（forward pass）のコストのわずかな定数倍で計算できる。

<!--en:cf8ffdd8-->
## 勾配の計算

<!--en:9a7f0043-->
### 順伝播

<!--en:e1a73137-->
まず、:numref:`sec_calculus` で扱った直線モデル $L(\mathbf{w}) = \|\mathbf{X}\mathbf{w} - \mathbf{y}\|^2$ を $\mathbf{w} = (1, 0)$ においてフレームワークのテンソルで定義し、順伝播のみを記述する。

<!--en:24a843c5-->
演算の記録と中間活性化値の保存はメモリを消費するため、フレームワークは勾配計算の対象として明示的に指定されたパラメータに依存する演算のみを追跡する。

<!--en:85210098-->
`w.attach_grad()` を呼び出すと、`w` が勾配追跡の対象として指定され、勾配バッファ `w.grad`（ゼロで初期化）が確保される。

<!--en:4291d98a-->
`w.requires_grad_(True)` を呼び出すと、`w` がインプレースで指定され、PyTorch は `w` を含む演算を追跡して得られた勾配を `w.grad` に格納する。

<!--en:c7aea1f1-->
`w` を `tf.Variable` でラップすると、勾配テープが自動的に監視する訓練可能なパラメータとなる。

<!--en:117f3d1f-->
次に、`L = loss(w)` を `with autograd.record():` ブロック内で評価し、MXNet に `w` から `L` までの演算を記録させる。

<!--en:5a5f91b6-->
次に `L = loss(w)` を評価すると、PyTorch は `w` から `L` までの演算の系列を自動的に記録する。

<!--en:9c74c5e4-->
次に、`L = loss(w)` を `with tf.GradientTape() as t:` ブロック内で評価し、TensorFlow に `w` から `L` までの演算をテープ `t` 上に記録させる。

<!--en:26ef09db-->
JAX は純粋関数型のアプローチをとる。配列は可変な勾配バッファをもたないため、`loss(w)` をそのまま評価しても通常の配列演算が実行されて `1.0` が返るだけである。その代わり、以下で微分する際には `jax.grad(loss)` が `loss` をトレースする。

<!--en:5bee0d8c-->
`grad_fn=<SumBackward0>` が `L` に付与されていることに注目しよう。これは計算グラフの最終演算を記録したものである。

<!--en:1dbba45a-->
記録されたトレースは :numref:`fig_autograd_graph` に示す*計算グラフ*を形成し、損失を $\hat{\mathbf{y}} = \mathbf{X}\mathbf{w}$、$\mathbf{r} = \hat{\mathbf{y}} - \mathbf{y}$、$\mathbf{s} = \mathbf{r} \odot \mathbf{r}$、$L = \sum_i s_i$ という 4 つの基本演算に分解する。

<!--en:77e38cac-->
![$L = \|\mathbf{X}\mathbf{w} - \mathbf{y}\|^2$ の $\mathbf{w} = (1, 0)$ における計算グラフ。$\mathbf{w}$ およびそこから計算される各値に 1 つずつノードがあり、定数 $\mathbf{X}$ と $\mathbf{y}$ は省略されている。また、$\mathbf{r} \odot \mathbf{r}$ は要素ごとの二乗を表す。各ノードにはその値（黒）と、それに関する $L$ の勾配（赤）を示す。順伝播（青）は左から右へ進み、逆伝播（赤）は $1$ を $L$ に与えて右から左へ各演算の局所規則を適用する。](../img/autograd-comp-graph.svg)

<!--en:e2e02f72-->
### 逆伝播

<!--en:cab06b1c-->
逆伝播（backward pass）を実行すると、出力における $\partial L/\partial L = 1$ から各ノードの局所微分規則を通じて $\mathbf{w}$ へと感度が逆向きに伝播する。

<!--en:687852ac-->
これにより、先ほどと同じ $(2, 4)$ が得られる。

<!--en:1da3ec35-->
`L.backward()` は逆伝播を実行し、勾配を `w.grad` に格納する。

<!--en:d81950c1-->
`t.gradient(L, w)` は、`L` の `w` に関する勾配をテープ `t` から計算する。

<!--en:2e8dce24-->
`jax.grad(loss)(w)` は勾配関数を `w` で評価する。

<!--en:dfdf2445-->
逆方向の局所規則では順伝播の中間活性化値（intermediate activation、ここでは $\mathbf{r}$ や $\mathbf{X}$ など）が必要になるため、訓練は推論（inference）よりも大幅に多くのメモリを消費する（:numref:`fig_autograd_memory`）。

<!--en:67689383-->
![出力 $\mathbf{h}_1, \ldots, \mathbf{h}_4$ をもつ 4 つの層を通る順伝播でのメモリ使用状況。(a) 勾配を追跡する場合、逆伝播（赤）で必要になるため、すべての出力が保持される。(b) 推論時のように勾配を追跡しない場合、次の層が使い終えた時点で出力を解放できる。](../img/autograd-activation-memory.svg)

<!--en:5bafdc1d-->
### 逆伝播の繰り返し

<!--en:2fe9e585-->
同じパラメータベクトル $\mathbf{w}$ で勾配をもう一度評価するとどうなるだろうか。

<!--en:3a89e956-->
`jax.grad(loss)(w)` は呼び出しのたびに新しい配列を返し、`w` に状態を保持しない純粋関数であるため、繰り返し呼び出しても副作用なしに常に `(2, 4)` を返す。マイクロバッチにわたって勾配を累積するには、返された配列を明示的に足し合わせればよい。

<!--en:93959838-->
MXNet はデフォルトで新しい逆伝播のたびに `w.grad` を上書きするため、再び `(2, 4)` が返される。

<!--en:8515fec6-->
PyTorch では `w.grad` が `(4, 8)` になる。これは PyTorch がデフォルトで新しい勾配を `w.grad` に*加算*するためであり、マイクロバッチや複数の損失項にわたって勾配を合計する際に便利である。標準的な訓練ループでは、次のステップの前に必ず `w.grad.zero_()` でバッファをクリアする。

<!--en:1a4fd689-->
`t.gradient(L, w)` は `w` に状態を保持せず新しいテンソルを返すため、再び `(2, 4)` が得られる。マイクロバッチにわたって勾配を累積するには、返されたテンソルを明示的に足し合わせる。

<!--en:ea810815-->
### ベクトル値関数

<!--en:685fbefd-->
ある演算が $m$ 個の出力からなるベクトル $\mathbf{u} \in \mathbb{R}^m$ を $n$ 個の入力 $\mathbf{x} \in \mathbb{R}^n$ から生成し、その $m \times n$ のヤコビ行列（Jacobian）を $\mathbf{J}$ とする。このとき、重みベクトル $\mathbf{v} \in \mathbb{R}^m$ をシードとして逆伝播を実行すると、転置を用いた*ベクトル・ヤコビ行列積*（vector–Jacobian product）$\mathbf{J}^\top \mathbf{v} = \nabla_{\mathbf{x}}(\mathbf{v}^\top \mathbf{u})$ が、$\mathbf{J}$ を明示的に構築することなく計算される。$\mathbf{v} = \mathbf{1}$ を例ごとの二乗誤差 $(r_1^2, r_2^2, r_3^2)$ に渡すと、その和が微分される。

<!--en:012c6d66-->
`losses.backward(v)` は $\mathbf{v}$ を受け取る（省略時のデフォルトは $\mathbf{1}$ である）。

<!--en:6202f257-->
非スカラーのテンソルに対して `backward()` を呼び出すには、`gradient=torch.ones(3)` によって $\mathbf{v}$ を明示的に渡す必要がある（`losses.sum().backward()` と等価である）。

<!--en:c8b5621d-->
`t.gradient` は `output_gradients` を通じて $\mathbf{v}$ を受け取る（省略時のデフォルトは $\mathbf{1}$ である）。

<!--en:56f63dc5-->
`jax.vjp(losses, w)` は順伝播の値と、$\mathbf{v}$ を $(\mathbf{J}^\top\mathbf{v},)$ に写す関数を返す。

<!--en:f5d36c16-->
## グラフの制御

<!--en:5054076c-->
### 値の切り離し

<!--en:a12480a2-->
テンソルの*切り離し*（detaching）とは、数値は同じだが計算グラフ上の祖先とのつながりをもたないビューまたはコピーを作る操作であり、誤差逆伝播法ではそのテンソルが定数として扱われる。$u = x^2$ と $z = u x$ を $\mathbf{x} = (0, 1, 2, 3)$ 上で考えよう（:numref:`fig_autograd_detach`）。$u$ がグラフに接続されたままであれば、勾配は両方の経路を流れて $\partial z/\partial x = 3x^2$ となる。一方、$u$ を切り離して $c$ とすると、$z = c x$ の微分では $c$ が定数として扱われ、$\partial z/\partial x = c = x^2$ が得られる（:numref:`sec_dqn` の深層 Q 学習のように、ネットワークが自身のブートストラップターゲットを計算する場合には不可欠である）。

<!--en:1fe60a00-->
![積 $z = ux$（ただし $u = x^2$）における、(a) 接続したままの場合と (b) 切り離した場合。青い矢印は順伝播の演算を表し、赤い矢印は逆伝播とそこで乗じられる局所導関数を表す。$u$ を切り離すと、同じ値をもつ定数 $c$ が作られ、$x$ とのつながりは断たれる。](../img/autograd-detach.svg)

<!--en:d370327f-->
`u.detach()` は、`u` と値を共有しつつ計算履歴を取り除いたテンソルを返す。

<!--en:eded9e78-->
`tf.stop_gradient(u)` は、`u` を順方向にはそのまま通し、逆方向の勾配を遮断する。

<!--en:6537b7d4-->
`jax.lax.stop_gradient(u)` は、微分対象の関数内で勾配を遮断する。

<!--en:7d9d00fd-->
対照的に、`z = u * x` を `u` の切り離しなしに直接計算すると、誤差逆伝播法は $z = x^3$ の両方の因子を通って伝播し、$\partial z / \partial x = 3x^2 = (0, 3, 12, 27)$ を返す。

<!--en:0b77f7b8-->
### 勾配追跡の無効化

<!--en:44c4d108-->
検証、推論、あるいはパラメータ更新 $\mathbf{w} \leftarrow \mathbf{w} - \eta \nabla L(\mathbf{w})$ の際には、それらの演算が損失の計算グラフに記録されないよう勾配追跡を無効化する。

<!--en:c6ef6e53-->
`autograd.record()` の外側のコードは記録されずに実行される。`w[:] = ...` は `w` をインプレースで更新しつつ `w.grad` を維持する。

<!--en:3e99d3fa-->
`with torch.no_grad():` は追跡を無効化する（`requires_grad=True` をもつリーフテンソルをインプレースで変更する際に必要である）。

<!--en:8f5847ed-->
`tf.GradientTape` の外側のコードは記録されずに実行される。`w.assign_sub(...)` は `w` をインプレースで更新する。

<!--en:fd254edc-->
`jax.grad` の外側では、配列演算はトレースされずに実行される。

<!--en:9fa8f97b-->
:numref:`sec_calculus` と同様、$\eta = 0.1$ による 1 ステップで $\mathbf{w}$ は $(1, 0)$ から $(0.8, -0.4)$ へ移動し、損失は $1$ から $0.4$ へと下がる。

<!--en:cde7bea8-->
## プログラムの微分

<!--en:08cc83c2-->
### 制御フロー

<!--en:6a4c84b4-->
自動微分は与えられた入力に対して*実際に実行された*基本演算の系列を記録するため、データに依存する `while` ループや `if` と `else` の分岐を含む Python 関数もそのまま微分できる。

<!--en:874ee0de-->
任意の非ゼロのスカラー $a$ に対して（$a = 0$ では `while` ループが終了しない）、`f(a)` は $2$（および場合によっては $100$）を掛ける定まった回数の乗算を実行するため、`f(a) = k * a` は局所的な傾き $k = f(a)/a$ をもつ区分線形（piecewise linear）関数となる（:numref:`fig_autograd_dynamic`）。具体的には、$a = 0.3$ のときは $12$ 回倍増されて $0.3 \times 2^{12} = 1228.8 \ge 1000$ に達し、正の分岐を通る（$k = 2^{12} = 4096$）。一方、$a = -0.75$ のときは $11$ 回倍増されて $-1536$ となり、`else` 分岐を通る（$k = 100 \times 2^{11} = 204{,}800$）。自動微分はこれら両方の傾きを正しく求める。

<!--en:a609f90f-->
![2 つの入力に対して `f` が記録した計算グラフ。$a = 0.3$ では、`f` は $a$ を $12$ 回倍増させて最初の分岐を実行する。$a = -0.75$ では、$a$ を $11$ 回倍増させて 2 番目の分岐を実行する。いずれのグラフも $a$ に関して線形であり、それぞれ固有の傾きをもつ。](../img/autograd-dynamic.svg)

<!--en:d983e5f5-->
なお、自動微分が微分するのは抽象的な数学的関数ではなく、*実行されたトレース*であることに注意しよう。ループ回数が切り替わる閾値では $f(a)$ は不連続になるが、自動微分は実行された側の分岐の傾きをそのまま返す。

<!--en:8dcc7309-->
## フォワードモードとリバースモード

<!--en:ec4a3859-->
写像 $\mathbf{f} : \mathbb{R}^n \to \mathbb{R}^m$ とその $m \times n$ ヤコビ行列 $\mathbf{J}$ に対して、連鎖律は順方向と逆方向のどちらの向きにもたどることができる（:numref:`fig_autograd_fwd_rev`、詳細は :citet:`Wengert.1964,Linnainmaa.1970` および :numref:`sec_mdl-matrix-calculus-autodiff` を参照）。

<!--en:2a33f32d-->
* **リバースモード（ベクトル・ヤコビ行列積、VJP）：**出力に $\mathbf{v} \in \mathbb{R}^m$ をシードとして与える逆方向スイープは $\mathbf{J}^\top \mathbf{v}$ を計算する。$j^\textrm{th}$ の標準基底ベクトル $\mathbf{v} = \mathbf{e}_j$ をシードとすれば、第 $j$ 行を $\mathbf{J}$ から取り出せる（ヤコビ行列全体を得るには $m$ 回のスイープを要する）。

<!--en:66ded8ad-->
* **フォワードモード（ヤコビ行列・ベクトル積、JVP）：**入力に接ベクトル $\mathbf{d} \in \mathbb{R}^n$ をシードとして与える順方向スイープは、値とともに微分値を順方向に伝播させて $\mathbf{J}\mathbf{d}$ を計算する。$\mathbf{d} = \mathbf{e}_i$ をシードとすれば、第 $i$ 列を $\mathbf{J}$ から取り出せる（ヤコビ行列全体を得るには $n$ 回のスイープを要し、メモリオーバーヘッドは定数の $2\times$ で済む）。

<!--en:ffb242db-->
![$m \times n$ ヤコビ行列 $\mathbf{J}$（$n$ 入力 $m$ 出力の関数のもの）を埋める 2 つの方法。(a) フォワードモード（計 $n$ 回のスイープ）、(b) リバースモード（計 $m$ 回のスイープ）。](../img/autograd-fwd-vs-rev.svg)

<!--en:0a96d980-->
MXNet はリバースモードの自動微分のみを実装している。

<!--en:2511c0e9-->
PyTorch は `torch.func.vjp`、`torch.func.jvp`、`torch.func.jacrev`、`torch.func.jacfwd` を提供している。

<!--en:34a5499e-->
TensorFlow は `GradientTape.jacobian`（リバースモード）と `tf.autodiff.ForwardAccumulator`（フォワードモード）を提供している。

<!--en:911ee726-->
JAX は `jax.vjp`、`jax.jvp`、`jax.jacrev`、`jax.jacfwd` を提供している。

<!--en:1621c5cb-->
スカラーの損失関数は出力が $m = 1$ 個、パラメータが $n$ 個であるため、そのヤコビ行列は 1 行のみの $\nabla_{\mathbf{w}} L^\top$ となる。リバースモード（*誤差逆伝播法*）は勾配の全 $n$ 成分を *1 回のスイープ*で計算できるのに対し、フォワードモードでは $n$ 回のスイープが必要になる。深層ネットワークの訓練でリバースモードが普遍的に使われているのはこのためである。

<!--en:30ac03ff-->
## まとめ

<!--en:5af680dd-->
自動微分は、順伝播の基本演算をトレースして計算グラフを構築し、局所微分規則を逆向きに適用することで厳密な勾配を計算する。これにより、直線モデルでも手書きの微分コードなしに $\nabla_{\mathbf{w}} L = (2, 4)$ を再現できた。中間値を切り離すと計算履歴が断たれ、誤差逆伝播法ではその値が定数として扱われる。一方、勾配追跡を無効化すれば、パラメータ更新や推論時の評価が計算グラフに記録されず、順伝播の活性化値のキャッシュも回避できる。計算グラフは与えられた入力に対して実際に実行された演算を記録するため、自動微分は Python のループや条件分岐もシームレスに微分できる。最後に、フォワードモードの 1 回のスイープはヤコビ行列・ベクトル積 $\mathbf{J}\mathbf{d}$（基底ベクトルのシード 1 つにつき 1 列）を計算するのに対し、リバースモードの 1 回のスイープはベクトル・ヤコビ行列積 $\mathbf{J}^\top\mathbf{v}$（基底ベクトルのシード 1 つにつき 1 行）を計算する。したがって、スカラーの損失（$m = 1$）に対しては 1 回の逆方向スイープだけで $n$ 個すべてのパラメータの勾配が得られる。

1. **マイクロバッチ：**3 個のマイクロバッチに対して続けて逆伝播を実行したとする。最後の勾配には何が入っており、3 つすべてを累積するにはどうすればよいか。

<!--en:4d0ad23c-2-->
2. **切り離された分岐：**`u = x * x` および `c = u.detach()`（または `stop_gradient(u)`）とする。$\nabla_{\mathbf{x}} \sum_i z_i$ は (a) `z = u * u`、(b) `z = u * c`、(c) `z = c * c` のそれぞれでどうなるか。

<!--en:173df157-2-->
3. **順方向スイープと逆方向スイープ：**物理シミュレータが $n = 3$ 個の翼形状パラメータを $m = 10^6$ 個のメッシュ圧力に写すとする。$10^6 \times 3$ のヤコビ行列全体をより高速に計算できるのはどちらの自動微分モードで、何回のスイープで済むか。

<!--en:557b98b6-2-->
**解答：**

<!--en:b0a55fb5-->
1. **3 番目のマイクロバッチの勾配のみ**（$\nabla_{\mathbf{w}} L_3$）。過去の結果には何も加算されないため、返された 3 つの勾配を明示的に合計する

<!--en:1c7a1c21-2-->
2. (a) `z = u * u = x^4` $\implies$ **$4\mathbf{x}^3$**、(b) `z = u * c = c * x^2` $\implies$ **$2c\mathbf{x} = 2\mathbf{x}^3$**（一方の因子が固定されるため $4\mathbf{x}^3$ の半分）、(c) `z = c * c` は `x` への有効な経路をもたない $\implies$ **$0$**（または `grad_fn` なし）

<!--en:299ddd4c-2-->
3. **フォワードモード（JVP）**は **$n = 3$ 回のスイープ**（1 列ごとに 1 回）のみで済むのに対し、リバースモードは $m = 10^6$ 回のスイープ（1 行ごとに 1 回）を要する
