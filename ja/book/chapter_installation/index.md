# インストール

<!--en:8f3faf64-->
本書を最大限に活用するには、実際にコードを動かし、書き換え、自分の手で実験してみるのがよい。すべての章は、実行可能な Jupyter ノートブックとして提供されている。ローカル環境の構築をできる限りスムーズにするため、対応する各フレームワーク向けに自己完結型の `.zip` バンドルを配布している（ページ上部の **Notebooks** メニューから入手できる）。各バンドルには、出力結果や図があらかじめ保存された状態でそのまま閲覧できるノートブック一式に加え、対応する `d2l` ライブラリのソースコード、および CPU 環境と GPU 環境の両方に対応したバージョン固定済みの [uv](https://docs.astral.sh/uv/) ロックファイルが含まれている。

<!--en:2e4f21f8-->
ノートブック内の計算済み出力を読むだけであれば深層学習ライブラリをインストールする必要はないが、コードを実行・変更するには Python、JupyterLab、および選択したフレームワークが必要になる。同梱の `uv` ロックファイルを使えば、数個のコマンドで動作確認済みの完全な環境をインストールできる。

<!--en:c640e612-->
## フレームワークの選択

<!--en:67f9fba9-->
特に強いこだわりがなければ、本書のすべての章を網羅している唯一のフレームワークである **PyTorch** から始めることを勧める。「基礎」（:numref:`chap_preliminaries` から :numref:`chap_rnn`）、「画像モデル」（:numref:`chap_cv`）、「深層学習のための数学」（:numref:`chap_mdl-linear-algebra` から :numref:`chap_mdl-dynamics`）、「深層学習のためのツール」（:numref:`chap_appendix_tools`）の各パートは、4 つのフレームワークすべて（PyTorch、JAX、TensorFlow、MXNet）で実装されている。「発展」パート（:numref:`chap_optimization` から :numref:`chap_diffusion`）は PyTorch と JAX で実装されており、「言語モデル」パート（:numref:`chap_lm_pretrained` 以降）は PyTorch で実装されている。

<!--en:654dccbc-->
始めるにあたって特別なハードウェアは必要ない。最初のいくつかの章は、最近の一般的なノートパソコンの CPU で快適に動作する。GPU は、後半でより大規模な畳み込みネットワーク、Transformer、生成モデルを訓練するときに有用となる。

<!--en:1be28c09-->
ダウンロード可能なノートブックのバンドルは、本ウェブサイトで公開されている本書の版と一致している。最新の開発版ソースファイル、ビルドスクリプト、開発環境を調べたい場合は、[GitHub](https://github.com/smolix/d2l-neu) からリポジトリを直接クローンすることもできる。

<!--en:0d8b8cd0-->
ただし、単にノートブックを読んで実行するだけであれば、フレームワーク別の `.zip` バンドルの方がはるかにサイズが小さく、ビルド時の依存関係も大幅に少なくて済む。

## CPU 環境の構築

<!--en:3f68b305-->
まずはセットアップを手早く確認するため、CPU 環境から始めることを勧める。展開したノートブックのディレクトリ内で、独立した Python 3.12 仮想環境を作成し、バージョン固定済みの CPU ロックファイルと同期する。

<!--en:0ebc3709-->
Apple Silicon 搭載の Mac で MXNet を実行する場合は、代わりに macOS 専用のロックファイルと同期する。

<!--en:ea000e91-->
Linux 上の MXNet では、`pylock.cpu.toml` は Linux `x86-64` 用の wheel として、本プロジェクトで[メンテナンスされている MXNet 2.0 リリース](https://github.com/smolix/mxnet/releases/tag/mxnet-2.0.0.zombie.1)で配布されているものを使用する。なお、MXNet のビルドは Linux（`x86-64`）および macOS（Apple Silicon）向けにのみ提供されている。Windows では、PyTorch、JAX、TensorFlow を使用するか、ホスト型のクラウド環境でノートブックを実行されたい。PyTorch、JAX、TensorFlow については、`pylock.cpu.toml` がオペレーティングシステムとアーキテクチャに適したパッケージを自動的に選択する。

<!--en:4d95a546-->
環境の同期が完了したら、JupyterLab を起動する。

<!--en:28f23ec3-->
通常、JupyterLab はデフォルトのウェブブラウザで自動的にタブを開く。開かない場合は、ターミナルに表示されるローカルの `http://localhost:...` という URL をコピーして貼り付ける。`--no-sync` を指定することで、`uv` は直前に `uv pip sync` で同期した CPU 環境または GPU 環境の中でそのまま実行される。

<!--en:0c4d418d-->
「言語モデル」パート（:numref:`chap_lm_pretrained` 以降）向けに、PyTorch バンドル（`d2l-pytorch.zip`）には `pylock.lm-cpu.toml` と `pylock.lm-gpu.toml` も同梱されている。これらは PyTorch に加えて、Hugging Face の `transformers` や `accelerate`、OpenAI クライアント、および検索・データキュレーション用のライブラリを追加するものである。こうした追加の依存関係は別の `.venv-lm` 仮想環境に分離し、メインの `.venv` を軽量に保つ。

## GPU 環境の構築

<!--en:48c6eb2f-->
同梱の GPU ロックファイルは、本書の実行に使用されたハードウェアアクセラレーション環境を再現するものであり、NVIDIA GPU を搭載した Linux（`x86-64`）マシンを対象としている。GPU 環境をインストールする前に、NVIDIA ドライバが有効で認識されていることを確認する。

<!--en:8c2464eb-->
展開したノートブックのディレクトリで、（まだ作成していない場合は）仮想環境を作成し、GPU ロックファイルと同期する。

<!--en:a65ba9af-->
CPU から GPU へ切り替えるために別の仮想環境を用意する必要はない。既存の環境で `uv pip sync pylock.gpu.toml` を実行すれば、CPU パッケージが対応する GPU パッケージへとクリーンに置き換えられる（同様に、PyTorch バンドルの「言語モデル」環境も `VIRTUAL_ENV=.venv-lm uv pip sync pylock.lm-gpu.toml` でアップグレードできる）。GPU ロックファイルでは、次のアクセラレータスタックがバージョン固定されている。

<!--en:92d52e20-->
* **PyTorch：**CUDA 12.8 の wheel

<!--en:17405190-->
* **JAX：**CUDA 12 の pip ディストリビューション

<!--en:30a2aa80-->
* **TensorFlow：**`and-cuda` ディストリビューション（CUDA ライブラリ同梱）

<!--en:aab96f43-->
* **MXNet：**メンテナンス版の CUDA 13.3 ビルド（`smolix/mxnet` 提供）

<!--en:47e45ce5-->
GPU のソフトウェアスタックはオペレーティングシステム、カーネルドライバ、GPU アーキテクチャに依存するため、バージョン固定済みのロックファイルが使用中のマシンの要件と異なる場合がある。`pylock.gpu.toml` がハードウェアや OS に合わない場合は、[PyTorch](https://pytorch.org/get-started/locally/)、[JAX](https://docs.jax.dev/en/latest/installation.html)、または [TensorFlow](https://www.tensorflow.org/install/pip) の公式インストールガイドを参照されたい。序盤の章では CPU ロックファイルを使用し、本書の後半で計算負荷の高い章に進んだ段階で、ホスト型ノートブック（:numref:`sec_hosted_notebooks`）やクラウド GPU インスタンス（:numref:`sec_cloud_instances`）に切り替えることもいつでも可能である。

## インストールの確認

<!--en:6f9cdc79-->
フレームワークが正しくインストールされているか、また GPU アクセラレータが検出されているかは、1 行のコマンドで確認できる。

<!--en:a63a46cd-->
CPU のみの環境では 2 行目に `False` と出力され、NVIDIA GPU が利用可能な場合は `True` と出力される。

<!--en:0099091a-->
CPU のみの環境では、`jax.devices()` は単一の CPU デバイスを表示し、NVIDIA GPU が利用可能な場合は代わりに GPU デバイスの一覧を表示する。

<!--en:1bb1e073-->
CPU のみの環境では、`list_physical_devices('GPU')` は空のリスト `[]` を返し、NVIDIA GPU が利用可能な場合は GPU デバイスの一覧を返す。

<!--en:f897c06d-->
CPU のみの環境では、`num_gpus()` は `0` を出力し、NVIDIA GPU が利用可能な場合は検出された GPU の数を出力する。

## 標準インポート

<!--en:3befd324-->
本書のすべてのノートブックは、標準のプリアンブルセルから始まる。このセルでは、スカラー関数や定数用の Python 組み込み `math` モジュール、CPU 配列用の NumPy（標準エイリアス `np`）、深層学習フレームワーク本体、そして `d2l` という名前で本書付属ライブラリの対応バックエンドをインポートする。

<!--en:e45921e3-->
ここで、`torch` は PyTorch の中核パッケージである。その `nn` モジュールはニューラルネットワークの層や損失関数を状態を持つクラスとして提供する一方、`F`（`torch.nn.functional`）は対応する演算を `F.relu` や `F.cross_entropy` のような状態を持たない関数として公開している。

<!--en:f0b6ed27-->
ここで、`jax` は関数変換（`jax.grad` や `jax.jit` など）および明示的な PRNG キー管理を提供し、`jnp` はアクセラレータに対応した NumPy 互換の配列インターフェースを公開している。ニューラルネットワークの層やモデルは Flax の `nnx` モジュールで構築し、`optax` のオプティマイザとスケジュールを使って訓練する。

<!--en:037884d1-->
ここでは TensorFlow を慣例的なエイリアス `tf` でインポートしており、高水準のニューラルネットワークの層やモデルの抽象化は `tf.keras` に収められている。

<!--en:2055c50f-->
MXNet の配列モジュールは NumPy API を模しているため、`mnp` としてインポートし、`np` が標準の NumPy を一意に指すようにしている。`npx` モジュールは深層学習向けの拡張機能を追加し、`autograd` は自動微分のための計算グラフを記録する。また、`gluon` と `nn` がニューラルネットワークの層を、`init` がパラメータのイニシャライザをそれぞれ提供する。`npx.set_np()` を呼び出すことで、MXNet の NumPy 互換の配列セマンティクスが有効になる。

<!--en:db60fd12-->
最後のインポート文は、本書付属パッケージの対応バックエンドを共通の名前 `d2l` に結び付ける。各節で `#@save` マーク付きの再利用可能な補助関数やクラスを定義・解説すると、それらは `d2l` にエクスポートされ、後の章で定義を繰り返すことなく簡潔に呼び出せるようになる。

<!--en:86174fac-->
本書を見やすく保つため、この標準インポートセルは、まさにこの箇所に一度だけ掲載する。ダウンロード版およびホスト型の Jupyter ノートブックでは、各ノートブックが単体で動作するようすべてのファイルの先頭にこのセルが含まれているが、ウェブ版と PDF 版では各節がそのトピック固有のコードから直接始まる。ノートブックで追加のライブラリ（強化学習の章における Gymnasium など）が必要な場合や、フレームワークを初期化する前にコンパイラフラグを設定する必要がある場合は、その追加のセットアップセルを明示的に掲載する。プロットのために特別な定型コードは必要なく、Jupyter はデフォルトで図をインライン描画する。

## データ、モデル、ディスク容量

<!--en:0663fe11-->
ノートブックの `.zip` アーカイブにはすべてのノートブック、計算済みのセル出力、および図が含まれているが、大規模な訓練データセットや事前学習済みモデルの重みは同梱されていない。その代わり、ノートブックは初回使用時にこれらのアセットを自動的にダウンロードし、ローカルのキャッシュディレクトリに保存する。そのため、ノートブックを読んで保存済みの出力を確認する作業は完全にオフラインでできるが、データを使用するノートブックを実行するにはインターネット接続と追加のディスク容量が必要になる。

<!--en:a9822b41-->
最後に、本書後半の一部の発展的な章では、一般的なノートパソコンが備える以上のメモリや計算資源が必要になる点に留意されたい。基礎的な章では CPU 環境から始め、処理負荷に応じてローカル GPU やクラウドマシンへ移行するとよい。深層学習用の専用ハードウェアの購入を検討している場合は、:numref:`sec_hardware_buyers` に選ぶ際のポイントをまとめた実践的なガイドがある。
