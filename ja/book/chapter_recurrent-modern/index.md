# 状態空間モデル

<!--en:392d9d59-->
:numref:`chap_rnn` のリカレントネットワークは、テキストを 1 トークンずつ順番に読み込み、それまでに読み込んだ内容を固定サイズの*状態*（state）に保持して引き継ぐ。したがって、100 万番目のトークンを生成するコストは、10 番目のトークンを生成するコストと変わらない。これに対し、:numref:`chap_transformers` の Transformer はすべてのトークンを保持する。長いレポートに関する質問に答える際には、レポートのすべてのトークンについてキーと値を保持するため（:numref:`sec_kv-cache`）、メモリもトークンあたりの計算量もコンテキスト長（context length）に応じて増大する。ところが :numref:`sec_gpt` では、そこで構築した GPT と同規模の単純なリカレントネットワークは、コンテキストの最初の数バイトを過ぎたところで遅れをとり、最後まで追いつくことはなかった。より優れたリカレントネットワークはその差を埋められるのだろうか。そして、増大するアテンションのコストはどの程度の長さから問題になり始めるのだろうか。

<!--en:3f113345-->
そこには 2 つの障壁が立ちはだかっている。古典的なリカレントネットワークは状態を非線形に更新するため、訓練を 1 ステップずつ進めざるを得ず、GPU の大部分をアイドル状態のまま遊ばせてしまう。また、固定サイズの状態は忘却を避けられないため、何を保持するかを選択しなければならない。その解決策は 3 つの方向から得られる。すなわち、1990 年代のゲート機構 :cite:`Hochreiter.Schmidhuber.1997,Gers.Schmidhuber.Cummins.2000`、制御理論における線形力学系（linear dynamical system）:cite:`Kalman.1960` を訓練可能な層として深層学習に導入した手法 :cite:`Gu.Dao.Ermon.ea.2020,Gu.Goel.Re.2022`、そしてソフトマックスを除いたアテンション :cite:`Katharopoulos.Vyas.Pappas.ea.2020` である。これら 3 つの流れは、並列に訓練でき、一種の線形アテンション（linear attention）を計算するリカレント層において合流する。本章で扱うすべてのリカレント層は、状態、各トークンを取り込む*更新*（update）、および出力を計算する*読み出し*（readout）を備えている。制御工学ではこのようなシステムを*状態空間モデル*（state space model）と呼ぶ。本章のタイトルではこの用語をこの広義の意味で用い、:numref:`sec_ssm` では連続時間の線形システムという狭義の意味で用いる。

<!--en:f74c7bba-->
まず、何を保持するかをネットワークが学習できるようにするゲート機構と、単一の状態ベクトルが計測可能なボトルネックを生む 2014 年のエンコーダ・デコーダから始める。続いて 3 つの改良により、状態を高速かつ選択的（selective）なものにする。すなわち、すべての位置にわたって並列に評価できアテンションと実行時間を比較できる線形更新（:numref:`subsec_linear-recurrence-cost`）、連続時間から離散化された複数時間スケールの減衰、そして各トークンがどれだけ書き込みどれだけ忘却するかを自ら決められるようにする入力依存のステップサイズである。さらに状態をベクトルから行列へと拡張すると、状態はキー・値ペアの連想メモリ（associative memory）となり、その記憶容量を計算できるほか、デルタ則（delta rule）によって書き込み規則を先鋭化できる。最後に、少数のフルアテンション層を挟み込むことで、いかなる固定サイズの状態も持ち得ない正確な想起（exact recall）を取り戻す。これは複数の実用言語モデルで採用されているハイブリッドな構成パターンである :cite:`Lieber.Lenz.Bata.ea.2024,Qwen.Team.2025`。

<!--en:dfa95979-->
初読の際には、:numref:`sec_seq2seq`、:numref:`sec_ssm` における連続時間の導出、および :numref:`sec_matrix-state` と :numref:`sec_deltanet` のチャンク化アルゴリズムは後回しにしてよい。特定の記憶能力を 1 つずつ切り分けるよう設計された小規模な合成タスクによって各メカニズムを検証し、:numref:`sec_gpt` のバイトレベルのテキストベンチマークによって各ミキサが言語上でどのような性能を示すかを確認する。

- **因果アテンション（$O(T)$ KV キャッシュ）：**トークンあたり 4 KB（KV ヘッド $8$ 個 $\times 128$、fp16）を保持し、**層あたり $512\text{ MB}$**（$T = 128\text{K}$ 時）へと増大してスコア計算に $O(T^2 d)$ FLOPs を要する

<!--en:c82e955b-->
- **再帰状態（$O(1)$ メモリ）：**履歴を固定サイズの **$2\text{ MB}$** の状態（Mamba-2、$d=4{,}096$ 時）に圧縮し、$T = 512$ トークンで KV キャッシュと交差する

<!--en:89f54574-->
- **中心的な問い：**$O(1)$ の状態を GPU 上で並列に訓練し、Transformer の想起能力に匹敵できるか

<!--en:3e921c00-->

[中心課題]{.kicker}

<!--en:7a0f3109-->
- **障壁 1（$O(T)$ の逐次深さ）：**非線形な $\tanh(\mathbf{W}_{\textrm{hh}}\mathbf{h}_{t-1})$ が GPU の並列性を阻害するのに対し、アフィン遷移（§{sec_linear-recurrence}〜§{num:sec_mamba}）は $O(\log_2 T)$ ラウンドの並列スキャンで実行できる

<!--en:d6715935-->
- **障壁 2（固定ベクトルの減衰）：**1D の状態 $\mathbf{h}_t \in \mathbb{R}^d$ は事実をぼやけさせるが、複数時間スケールの $\Delta_t$、行列状態 $\mathbf{S}_t \in \mathbb{R}^{d_v \times d_k}$、およびデルタ則（§{sec_ssm}〜§{num:sec_deltanet}）がキー・値アドレッシングを加える

<!--en:3508a84f-->
- **統一的な状態空間の視点：**すべてのミキサは**状態**、**書き込み更新**、および**読み出し**を備える
