# 系列生成のための強化学習

<!--en:de3f025a-->
本書でここまで扱ってきた言語モデルはすべて、テキストを模倣するように訓練されていた。すなわち、コーパスの書き手に対する行動クローニング（behavior cloning、:numref:`sec_imitation`）である。今日実際に使われているモデルは、コーパスには含まれない信号を用いてさらに訓練される。解答の最終的な答えが正しいかを判定器が判定したり、2 つの応答のどちらが優れているかを読み手が評価したりする信号である。そのスコアは、モデル自身が書き上げた応答全体の後に一度だけ与えられ、模倣すべき正解トークンは存在しない。:numref:`sec_policygradient` と :numref:`sec_baselines` では、4 つの算術プロンプトと判定器を用いて、この設定で方策（policy）を訓練した。

<!--en:4eda153a-->
この着想自体は、こうしたモデルよりも古い。:citet:`Christiano.Leike.Brown.ea.2017` は人間の比較データに報酬を当てはめ、方策勾配（policy gradient）によって最適化した。:citet:`ouyang2022training` は大規模言語モデル（large language model）に対してこれを実施し、教師ありモデルからの乖離に対するペナルティを加えた。さらに :citet:`Shao.Wang.Zhu.ea.2024` は価値ネットワークをサンプルのグループに置き換え、:citet:`DeepSeekAI.2025` は学習された報酬を判定器に置き換えた。

<!--en:7326a04c-->
報酬が応答ごとに 1 つの数値で与えられるとき、トークンごとの視点は何をもたらすのだろうか。また、抜け穴を見つけた方策を :numref:`sec_regularized` のペナルティはどこまで抑止できるのだろうか。これらの問いへの答えから、:numref:`sec_baselines` のグループ重み、:numref:`sec_ppo` の確率比とクリッピング、そしてこのペナルティを組み合わせた事後学習（post-training）の更新則が導かれる。

## 軌跡としての応答

<!--en:797f7d50-->
### 1 つの勾配と 2 つの視点

<!--en:b1b32769-->
応答 $y = (a_1, \ldots, a_T)$ は、プロンプト $x$ に対してトークンを行動として生成される軌跡（trajectory）である（:numref:`tab_rl_sequence_dictionary`）。トークン $t$ の直前の状態はプレフィックス $s_t = (x, a_1, \ldots, a_{t-1})$ であり、そこに $a_t$ を追加すると確率 1 で $s_{t+1}$ へ遷移する。したがって、応答の確率はトークン確率の積 $\pi_\theta(y \mid x) = \prod_t \pi_\theta(a_t \mid s_t)$ となり、次式が成り立つ。

<!--en:cf64cfa3-->

<!--en:d7e178ad-->

<!--en:fa5adcef-->

<!--en:e7b7f908-->

<!--en:1cc56631-->

<!--en:b4a3d415-->
:eqref:`eq_seq_factorization` の左辺は応答を 1 つの行動として扱い、右辺は $T$ 個のトークン行動として扱う。最後に 1 つの報酬 $r(x, y)$ のみが与えられ割引がない場合、すべてのトークンの残りの累積報酬（reward-to-go）は $r(x, y)$ になる。そのため、どちらの視点でも各トークンのスコアには同じ*応答重み*（response weight）$r(x, y) - b(x)$ が掛けられる。ここで $b(x)$ はプロンプトのみに依存する任意のベースラインである。

<!--en:72d1ec15-->
### 応答内の信頼割り当て

<!--en:71ab46fe-->
応答重みは不偏であるが、すべてのトークンを同等に扱う。しかし、誤答の中にも正しいトークンが含まれていることがある。プロンプト `3*4` に対して、十の位 $a_1$ と一の位 $a_2$ がそれぞれ $0, \ldots, 9$ から一様に選ばれて応答されるとする。正解は `12` のみであるため、$V(x) = 1/100$、$V(x, 1) = 1/10$ であり、他のすべての十の位に対しては $V(x, a_1) = 0$ である。応答 `13` はスコア $0$ となり、両方のトークンに重み $r - V(x) = -0.01$ を受け取るため、正しい十の位の確率まで押し下げてしまう。これに対し、:numref:`sec_baselines` のトークンアドバンテージはプレフィックスで条件付けるため、十の位は $A(s_1, a_1) = V(x, a_1) - V(x) = +0.09$、一の位は $A(s_2, a_2) = r - V(x, a_1) = -0.1$ を受け取る。関数 `token_credit` は、$\pi(y \mid x)$、応答重み、および両方のアドバンテージを 100 通りすべての応答 $y = 10 a_1 + a_2$ について計算する。

<!--en:e06d3ea5-->
3 つの応答に対する 3 種類の重みを表示し、応答重みと十の位のアドバンテージが十の位（そのスコアは $\mathbf{e}_{a_1} - \mathbf{p}_1$）に対して同じ期待勾配を与えることを確認したうえで、いずれも平均が 0 である各重みの分散を比較する。

<!--en:3ae87441-->
応答重みの分散は、十の位のアドバンテージの 11 倍に達する。応答重みは $r - V(x) = \big(V(x, a_1) - V(x)\big) + \big(r - V(x, a_1)\big) = A(s_1, a_1) + A(s_2, a_2)$ のようにテレスコーピング分解でき、第 2 項はどのプレフィックスを条件としても平均が 0 になるため 2 つの項は無相関であり、分散は $0.0099 = 0.0009 + 0.0090$ と単純に加算される。各トークンのスコアは他のすべてのトークンのノイズを背負い込み、その数は $T$ 個のトークンに対して $T$ 項にのぼる。

<!--en:172607a2-->
### 必要な構成要素と任意の構成要素

<!--en:082db8d0-->
既知の遷移と単一の終端報酬（terminal reward）という性質により、本章の手法の多くは不要になる。応答は有限長であるため $\gamma = 1$ でよく、遷移モデル（transition model）を学習する必要はなく、生成は任意のプレフィックスから再開できる。また、オフポリシーでブートストラップすることもないため、:numref:`sec_dqn` の死の三要素（deadly triad）も生じない。応答重みは不偏であり、:numref:`sec_baselines` のグループ平均が RLOO :cite:`Ahmadian.Cremer.Galle.ea.2024` や GRPO のようにネットワーク不要のベースラインとなるため、クリティックも任意である。一方、各プレフィックスに価値ヘッドを設けるか :cite:`ouyang2022training`、VinePPO のようにプレフィックスから続きをサンプリングすれば :cite:`Kazemnejad.Aghajohari.Portelance.ea.2025`、トークンごとの信頼割り当て（credit assignment）が得られる。結局のところ必要として残るのは、ベースライン付きのスコア、各更新ステップの上限、そして報酬の誤りに対する防御である（:numref:`fig_rl_token_mdp`）。

<!--en:9009337e-->
## 検証器・報酬モデルとその抜け穴

<!--en:cab4da86-->
報酬は、人間の比較データに当てはめたモデル（:numref:`sec_regularized`；比較データが存在しない領域で最も信頼性が低くなる）から得られるか、テストハーネスや完全一致採点器のような判定から得られる。こうした判定に対して訓練する手法は*検証可能な報酬からの強化学習*（reinforcement learning from verifiable rewards、RLVR）と呼ばれ、近年の推論モデルの訓練に用いられている :cite:`DeepSeekAI.2025`。判定器は検査対象の性質については厳密であるが、それが本来意図した性質であるとは限らない。

<!--en:80aa4186-->
### KL ペナルティ付きグループステップ

<!--en:a36c1ba3-->
:numref:`sec_mdp` の検証器タスクでは、通常の候補の中に `8*8` や `9*9` に答えられるものはなく、9 番目の候補である*ヘッジ*「4、12、64、81 のいずれか」は、通常の各候補に対して参照確率が $e^{-4}$ 倍となっている。`sloppy_checker` は正解文字列を含むあらゆる応答を受理するため、すべてのプロンプトでこのヘッジに報酬を与えてしまう。

<!--en:ddbe60d4-->
この寛容な判定器に対して訓練すると、方策はこのヘッジを見つけ出す。:numref:`sec_regularized` のペナルティ $\beta\, D_{\textrm{KL}}\big(\pi(\cdot \mid x) \Vert \pi_{\textrm{ref}}(\cdot \mid x)\big)$ は報酬に折り込むことができ、サンプリングされた各応答を $r(x, y) - \beta \log\big(\pi_\theta(y \mid x) / \pi_{\textrm{ref}}(y \mid x)\big)$ で評価すればよい。内部の $\log \pi_\theta$ を微分しても $-\beta\, \mathbb{E}[\nabla_\theta \log \pi_\theta] = 0$ が加わるだけであるため、REINFORCE 推定量は不偏のままである。$T > 1$ トークンの場合、対数確率比はトークンごとの対数確率比の和になり、終端報酬が各トークンでの報酬へと変換されるため、各トークンの重みにはそのトークン以降の対数確率比のみを残せばよい（演習問題 :exref:`ex_rl-sequences-kl-loss`c）。`kl_group_step` は、このペナルティ付き報酬を :numref:`sec_baselines` のグループステップ `d2l.group_step` に渡す。

<!--en:8fb8053d-->
$\beta$ はどれほど大きくすべきだろうか。最適解は報酬によって参照方策を傾けた分布 $\pi^\star(y \mid x) = \pi_{\textrm{ref}}(y \mid x)\, e^{r(x, y)/\beta} / Z(x)$ である（:numref:`sec_regularized`）。`8*8` では寛容な判定器がヘッジにのみ報酬を与えるため、通常の候補に対するオッズは $e^{-4}$ から $e^{-4} e^{1/\beta}$ へと上昇する。したがって、ヘッジの方が高確率になるのはちょうど $\beta < 1/4$ のときであり、$\beta = 0.2$ では $e \approx 2.7$ 倍の確率になる。一方、`2+2` と `3*4` では正解にも報酬が与えられるため、オッズは $e^{-4}$ のままであり、しきい値は存在しない。

<!--en:5b450b68-->
### 閉形式解とのスイープ比較

<!--en:ba2d7805-->
$K = 32$ として $400$ 回の更新にわたる訓練を $\beta$ の 5 つの値で実行し、最後の $100$ 個の方策を平均して、寛容スコア・厳密スコア・ヘッジの平均確率を表示する。あわせて、傾斜最適解（tilted optimum；選好値で表せば参照方策に報酬を $\beta$ で割った値を加えたもの）に対する同じ数値も並べて示す。

<!--en:8bb2591d-->
$\beta = 0$ では、方策は満点の寛容スコアを獲得するものの、厳密な評価では $0.50$ にとどまり、`8*8` と `9*9` では確率のすべてがヘッジに集中する。$\beta = 0.1$ や $0.2$ でもヘッジが依然として優位である。しかし $1/4$ を超えると逆転し、$\beta = 0.3$ では `8*8` におけるヘッジの確率が通常の各候補の約半分になり、$e^{-4} e^{1/0.3} \approx 0.5$ の予測と一致する。その代償として有用な学習も阻害され、$\beta = 0.5$ では厳密スコアが約 1/4 まで低下する。訓練結果の各行は最適解から約 $0.02$ 以内に収まっているが、わずかな系統的ずれが残る。これは $\pi^\star$ の近傍ではグループ内のペナルティ付き報酬がほぼ等しくなり、反復が収束すべきまさにその場所で標準化がステップを拡大してしまうためである。ペナルティはどの $\beta$ においても抜け穴に価格を付けるだけであり、抜け穴そのものを塞ぐことは決してない。

## 事後学習の更新則

<!--en:0a137340-->
### 古いサンプルに対する確率比

<!--en:fb052f1e-->
ここまでの更新はすべて、新しく生成したグループを一度だけ使っていた。しかし大規模な事後学習ではそうはいかない。訓練器とはカーネルや演算精度が異なる推論エンジンが応答を生成し、複数の勾配ステップが各バッチを共有するからである。サンプルは古い方策 $\pi_{\theta_{\textrm{old}}}$ から得られるため、トークン $t$ には確率比 $\rho_t = \pi_\theta(a_t \mid s_t) / \pi_{\theta_{\textrm{old}}}(a_t \mid s_t)$ で重みを付け、:numref:`sec_ppo` と同様にクリップする。応答全体に対する確率比 $W$ とその幾何平均 $\bar\rho$ は次式で与えられる。

<!--en:f266b8c0-->
積 $W$ は厳密な補正を与えるが、その対数はノイズを含む $T$ 個の項の和になるため、長い応答では何桁にもわたって変動する。グループ系列方策最適化（Group Sequence Policy Optimization、GSPO）は代わりに $\bar\rho$、すなわち系列長とともにスケールが増大しない応答あたり 1 つの数値をクリップする :cite:`Zheng.Liu.Li.ea.2025`。

<!--en:ab5eb999-->
### 非対称なクリッピング許容帯

<!--en:959d12ed-->
確率比空間における固定幅の許容帯は、許容する確率の変化量が元の確率によって異なる。$\epsilon_{\textrm{clip}} = 0.2$ のとき、確率 $0.01$ のトークンは $0.012$ を超えて上昇しても報酬上の利得がなく、確率 $0.6$ のトークンは $0.72$ を超えても利得がない。大半が低頻度トークンからなる数万語の語彙においては、有用な低頻度トークンの確率がゆっくりとしか伸びずエントロピーが低下してしまう。そこで DAPO は上側の上限のみを $1 + \epsilon_{\textrm{high}}$（ただし $\epsilon_{\textrm{high}} = 0.28$）へと引き上げる :cite:`Yu.Zhang.Zhu.ea.2025`（演習問題 :exref:`ex_ppo-asymmetric-bands`）。

<!--en:c99c8448-->
### グループ相対方策最適化

<!--en:ff81ddba-->
グループ相対方策最適化（Group Relative Policy Optimization、GRPO）:cite:`Shao.Wang.Zhu.ea.2024` は、これらの要素を組み合わせた手法である。プロンプトごとに $K$ 個の応答を $\pi_{\theta_{\textrm{old}}}$ からサンプリングし、応答 $j$ のすべてのトークンに :numref:`sec_baselines` の標準化された重み $\hat{A}_j = (r_j - \bar{r}) / (\sigma_r + 10^{-8})$ を与える。ここで、$\bar{r}$ と $\sigma_r$ はグループ内の報酬の平均と標準偏差である。そして同じグループ上で複数エポックにわたり、次の目的関数を最大化する。

<!--en:e4ad746e-->
ここで、$T_j$ は応答 $j$ の長さであり、$k_3 = \pi_{\textrm{ref}}/\pi_\theta - \log(\pi_{\textrm{ref}}/\pi_\theta) - 1$ はサンプリングされたトークンにおいて評価される。最小値演算は、確率比が有利な側で許容帯を超えた時点でそのサンプルの勾配を切り捨てる。クリッピングはサンプリング方策と比較して各更新を制限し、ペナルティは固定された参照方策と比較して最適解そのものを変化させる。

<!--en:808d8e58-->
`grpo_step` は、すべての応答が 1 トークンである検証器タスク上でこの目的関数を実装したものである。`num_epochs` 回の各パスでは、サンプリング方策に対する確率比を計算し、クリップされた項が依然として $\theta$ に依存するサンプル（`live`）を残して勾配上昇ステップを 1 回実行する。ここで、$\rho\,\hat{A}$ と $-\beta k_3$ の勾配は、それぞれ $\rho\,\hat{A}$ と $-\beta(1 - \pi_{\textrm{ref}}/\pi_\theta)$ にスコア $\mathbf{e}_y - \pi_\theta(\cdot \mid x)$ を掛けたものになる。

<!--en:caef0f6b-->
プロンプトあたり $32$ 個の応答からなる 1 つのグループを 4 エポックにわたって再利用し、各エポックにおける確率比の範囲と許容帯 $[0.8, 1.2]$ の外に出た割合を表示したうえで、同じグループに対する 1 ステップのみの更新と比較する。

<!--en:927e4af8-->
第 1 エポックでは方策がまだ動いていないため、すべての確率比は $1$ である。1 ステップ後には正解の確率比はすでに $1.5$ を超えている。クリッピングは 1 回のステップ幅そのものを抑えるのではなく、許容帯を超えた増加にそれ以上の報酬を与えないようにするだけだからである。その後、許容帯の外に出る割合は増えていき、ほぼすべてのグループで第 2 エポックより第 4 エポックの方が大きくなる。40 個のグループで試したところ、4 エポックの更新は常に 1 エポックよりも高い厳密スコアで終了した。

<!--en:85a1b9c7-->
$k_3$ 項は、報酬に折り込んだペナルティとは異なる仕方で方策を抑制する。$\pi_\theta$ のもとでの期待値は $D_{\textrm{KL}}(\pi_\theta \Vert \pi_{\textrm{ref}})$ であるが、サンプルを固定したまま微分すると、順方向ダイバージェンス $D_{\textrm{KL}}(\pi_{\textrm{ref}} \Vert \pi_\theta)$ の期待勾配を持つようになる :cite:`Tang.Munos.2025`（演習問題 :exref:`ex_rl-sequences-kl-loss`）。:numref:`subsec_kl_direction` で見た 2 つの向きは、抜け穴に対して大きく異なる振る舞いを示す。`8*8` において $\beta = 0.5$ としたとき、逆方向の最適解はヘッジの確率を $0.017$ に抑えるのに対し、順方向の最適解では $0.50$ に達する。順方向ダイバージェンスは、参照方策の通常の候補を無視することにはペナルティを課すが、参照方策がめったに選ばなかった候補へ確率を移すことには課さないためである。

<!--en:dd7307fc-->
広く使われている 2 つの派生手法は、これらの設計選択を調整している。DAPO はペナルティを省き、上側のクリップを引き上げ、報酬がすべて等しいグループを破棄する :cite:`Yu.Zhang.Zhu.ea.2025`。Dr. GRPO は $\sigma_r$ および応答長による除算（:numref:`subsec_pg_loss_divisor`）を取り除く :cite:`Liu.Chen.Li.ea.2025`。

したがって、あらゆる方策は（比較からは観測できないプロンプトのみの項を除いて）自らを最適とする報酬を定義する。これを Bradley-Terry 尤度に代入すると、報酬の当てはめはサンプリングも報酬モデルも不要な方策自体の分類損失へと変わる。これが*直接選好最適化*（direct preference optimization、DPO）である :cite:`Rafailov.Sharma.Mitchell.ea.2023`。そのデータは固定された比較データの集合であるため、:numref:`sec_offline` の論点をそのまま引き継ぐことになる。

<!--en:1a0e29e1-->
本節の議論はすべて、1 ターンかつ単一の終端報酬という前提に立っており、それゆえに応答全体に対する文脈付きバンディット（contextual bandit、:numref:`sec_exploration`）となっている。ツール呼び出し、環境からのフィードバック、複数ターンの対話が加わると遷移カーネル（transition kernel）が再び現れ、それに伴ってクリティックと信頼割り当て問題も復活する。「言語モデル」パートでは大規模な事後学習を扱い、:numref:`sec_deep_rl-further-reading` では派生手法とプロジェクトをまとめる。

<!--en:9a272665-->
本章は、数十万ステップを要した振り子の課題から始まった。CartPole では 1 ステップのクリティックはステップ数を節約できなかったが、バッチあたり 4 エポックの PPO はステップ数を半減させ、DQN は 35,000〜45,000 ステップを要した。Pendulum ではソフトアクタークリティックが数千ステップ、学習されたモデルが計算量と引き換えに数百ステップで済んだ。さらにオフライン学習器は新たなステップを一切必要とせず、グループ上での 4 エポックの反復は同じサンプルから方策をより遠くまで進めた。こうした節約はいずれも、誤りうる何らかの推定に依拠している。すなわち、クリティック、古いバッチ、モデル、ログ、あるいは判定器である。

## まとめ

<!--en:3e8fbc4c-->
応答はトークンの軌跡であり、応答単位とトークン単位の両視点は同一の勾配を与える。単一の終端スコアはすべてのトークンに重み $r - b(x)$ を与え、その分散は各トークンアドバンテージの分散の和になる。プレフィックス価値はクリティックや再生成のコストと引き換えに各トークン固有の信頼割り当てを与えるが、応答重みが不偏であるためクリティックは任意である。KL ペナルティは判定器の抜け穴に対し、しきい値も含めて傾斜最適解が予測するとおりの価格を付ける。GRPO はグループ重み、クリップされた確率比、および $k_3$ ペナルティを組み合わせるが、その勾配は順方向ダイバージェンスの勾配であるため、ヘッジをほとんど抑制しない。

## 演習問題

<!--en:ef72f53f-->
1. **軌跡内のツール出力。** ツールを呼び出すモデルがトークン列 $y^{(1)}$ を出力し、ツールの出力 $o \sim P_{\textrm{tool}}(\cdot \mid x, y^{(1)})$（これは $\theta$ に依存しない）を受け取った後、トークン列 $y^{(2)}$ を出力するとする。検証器は $\tau = (x, y^{(1)}, o, y^{(2)})$ に対して一度だけスコアを付け、報酬 $r(\tau)$ を与える。
    1. $\tau$ の確率とその対数の勾配を書き下せ。どのトークンがスコア項に寄与するか。
    1. 系列全体に対して対数確率を評価する訓練ループは、ツールの出力に対するモデル自身の確率を用いて $\big(r(\tau) - b(x)\big)\, \nabla_\theta \log \pi_\theta(o \mid x, y^{(1)})$ という項を加えてしまう。重みが定数であってもこの項の期待値は一般に 0 にならないことを示し、スコアの平均が 0 になるという証明のどの段階が破綻するかを述べよ。この項はモデルに何を学習させてしまうか。

<!--en:2ca8e60d-->
1. **2 桁の応答。** :numref:`subsec_rl_sequences_credit` の 2 つの桁が、それぞれ独自の選好値のソフトマックスである分布 $\mathbf{p}_1$ と $\mathbf{p}_2$ から抽出され、検証器は正解に対してのみ $1$ を支払うとする。
    1. 応答重み $r - V(x)$ とトークンアドバンテージが、各位置の選好値に対して同じ期待勾配を与えることを示せ。どの条件付き期待値によって両者は一致するか。
    1. $A(s_1, a_1)$ と $A(s_2, a_2)$ が無相関であることを示し、$T$ トークンの応答に対する同様の結果を述べよ。
    1. 確率 $0.9$ を第 1 位置の数字 $1$ と第 2 位置の数字 $2$ に与え、他のすべての数字に $1/90$ を与える方策において `token_credit` を呼び出せ。このとき応答重みを $A(s_1, a_1)$ に置き換えると十の位の更新の分散はどれだけ減少するか。また、一様方策のときより減少幅が小さいのはなぜか。
   :exlabel:`ex_rl-sequences-two-digit-responses`

<!--en:6c4dd565-->
1. **ヘッジに対する 2 つのしきい値。** $\pi^\star$ を、報酬 `sloppy` と参照方策 `task.pi_ref` に対する傾斜最適解とする。
    1. `8*8` と `9*9` では、ヘッジが `sloppy` によって報酬を与えられる唯一の応答である。$\pi^\star$ のもとでのヘッジの確率を $\beta$ の関数として書き下せ。どの $\beta$ で他の 8 つの各応答と同じ確率になり、どの時点で確率全体の半分を占めるようになるか。この 2 つのうち、本文で述べたしきい値はどちらか。
    1. `2+2` と `3*4` では、正解の応答とヘッジの両方に報酬が与えられる。$\pi^\star$ は $\beta \to 0$ のときヘッジにどれだけの確率を与えるか。
    1. $\beta = 0$ での訓練は、`2+2` と `3*4` においてヘッジにほとんど確率質量を置かなかったが、報酬のある 2 つの応答へのどのような確率配分であっても正則化なしの目的関数を最大化する。`d2l.group_step` の更新のどの性質が、訓練の到達した配分を選択したのか。
   :exlabel:`ex_rl-sequences-two-thresholds`

<!--en:890bce52-->
1. [code] **有限インスタンス上の DPO。** ● 同じプロンプトに対してともに `task.pi_ref` から抽出された 2 つの応答間の選好が、報酬 `sloppy` を持つ Bradley-Terry モデルに従うとする。選好された応答と棄却された応答をそれぞれ $y_w$、$y_l$ と書き、$h_\theta(y) = \log\big(\pi_\theta(y \mid x) / \pi_{\textrm{ref}}(y \mid x)\big)$ とおく。
    1. :eqref:`eq_dpo_reward` を Bradley-Terry モデルに代入し、1 ペアあたりの負の対数尤度が $-\log \sigma\big(\beta\, h_\theta(y_w) - \beta\, h_\theta(y_l)\big)$ になることを示せ。ここで $\sigma$ はロジスティック関数である。なぜ $Z(x)$ は現れないのか。
    1. 無限個のペアがあるとき、期待損失が傾斜最適解によって最小化されることを示せ。このことは演習問題 :exref:`ex_rl-sequences-two-thresholds`a のしきい値に対して何を意味するか。
    1. プロンプトあたり $1000$ 個のラベル付きペアを抽出し、$\beta = 0.5$ における平均損失を、ステップサイズ $10$ の勾配降下法で `task.theta_ref` から出発して選好テーブル上で最小化せよ。5 つのシードにわたり、$200$、$2000$、$20000$ ステップ後の各プロンプトにおけるヘッジの確率を報告せよ。ヘッジが比較で一度も負けないプロンプトでは何が起きるか。また、なぜ $\beta$ はそれを防げないのか。

<!--en:ebea4bff-->
1. **損失としての KL 項。** ●● GRPO はサンプリングされた各トークンで $\beta k_3$ を引き、トークンを固定したまま微分する :cite:`Shao.Wang.Zhu.ea.2024`。:citet:`Tang.Munos.2025` は、このような損失が何を最適化するかを解析している。
    1. 1 トークンの応答に対して $h = \log\big(\pi_\theta(y \mid x) / \pi_{\textrm{ref}}(y \mid x)\big)$ と書き、損失 $k_1 = h$、$k_2 = h^2 / 2$、$k_3 = e^{-h} + h - 1$ を比較せよ。$y \sim \pi_\theta$ のとき、$k_1$ の期待勾配は 0 であり、$k_2$ の期待勾配は $\nabla_\theta D_{\textrm{KL}}(\pi_\theta \Vert \pi_{\textrm{ref}})$、$k_3$ の期待勾配は $\nabla_\theta D_{\textrm{KL}}(\pi_{\textrm{ref}} \Vert \pi_\theta)$ であることを示せ。
    1. 順方向ペナルティ $\beta\, D_{\textrm{KL}}(\pi_{\textrm{ref}} \Vert \pi)$ のもとでは、最大点は $\pi(y) = \beta\, \pi_{\textrm{ref}}(y) / \big(m - r(y)\big)$ となる。ここで乗数 $m > \max_y r(y)$ は確率の総和を 1 にする定数である（演習問題 :exref:`ex_regularized-forward-kl-penalty`a）。`8*8` で報酬 `sloppy` を用いた場合について、$m$ を $\beta \in \{0.1, 0.25, 0.5\}$ で数値的に求め、ヘッジの確率を傾斜最適解のもとでの確率と比較せよ。両者の差は $\beta$ にどう依存するか。
    1. $T$ トークンの応答に対し、$h_t$ をトークン $t$ の対数確率比と書き、:eqref:`eq_seq_factorization` を用いて次式を示せ。

       $$\nabla_\theta D_{\textrm{KL}}\big(\pi_\theta(\cdot \mid x) \Vert \pi_{\textrm{ref}}(\cdot \mid x)\big) = \mathbb{E}\Big[\sum_{t=1}^{T} \nabla_\theta \log \pi_\theta(a_t \mid s_t) \sum_{t'=t}^{T} h_{t'}\Big].$$

       トークンごとの損失 $k_2$ の和はどの項を見落とすか。また、`kl_group_step` のようにペナルティを報酬に折り込むと、なぜこの見落としが回避されるのか。
   :exlabel:`ex_rl-sequences-kl-loss`

<!--en:ca43af9e-->
1. **非対称な許容帯。** あるトークンがサンプリング方策のもとで確率 $0.01$ を持つとする。各バッチがその確率を、クリッピングがそれ以上の増加への報酬を打ち切る倍率 $1 + \epsilon_{\textrm{high}}$ だけちょうど引き上げ（:numref:`subsec_ppo_asymmetric`）、次のバッチは更新後の方策からサンプリングされるとする。
    1. 確率を $0.01$ から $0.5$ まで引き上げるのに、$\epsilon_{\textrm{high}} = 0.2$ では何バッチかかり、$\epsilon_{\textrm{high}} = 0.28$ では何バッチかかるか。
    1. 2 行動の問題において、もう一方の行動の初期確率は $0.99$ である。このような 1 バッチの更新後における、その行動の確率比を計算せよ。まれにしかサンプリングされない行動が確率を増やせる速さを制限しているのは、どちらの行動に適用された許容帯のどちら側か。
    1. 2 行動の場合、上側のクリップが高確率側の行動（確率 $p$）の増加を制限するのは $(1 + \epsilon_{\textrm{high}})\, p < 1$ の間だけである。どのような $p$ に対して $\epsilon_{\textrm{high}}$ を $0.2$ から $0.28$ へ引き上げると高確率側の行動まで速く増加するようになり、それはエントロピーにどのような影響を与えるか。また、大半が低頻度トークンである数万語の語彙を持つ言語モデルでは、同じ変更によってなぜエントロピーが高く保たれるのか。
   :exlabel:`ex_ppo-asymmetric-bands`

<!--en:01c81796-->
1. **長さ正規化された確率比。** ● GSPO :cite:`Zheng.Liu.Li.ea.2025` は、重みとしてもクリップの内部でも、トークンごとの確率比を :eqref:`eq_seq_ratio` の幾何平均 $\bar\rho = W^{1/T}$ に置き換える。サンプリング方策のもとでのトークンごとの対数確率比 $\log \rho_t$ を、平均 $-d$、分散 $v$ の独立同分布に従う確率変数としてモデル化せよ。ここで $d$ はトークンあたりのダイバージェンス $D_{\textrm{KL}}(\pi_{\theta_{\textrm{old}}} \Vert \pi_\theta)$ である。
    1. $\log W$ が平均 $-d T$、分散 $vT$ を持つ一方、$\log \bar\rho$ は平均 $-d$、分散 $v / T$ を持つことを示せ。
    1. $\mathbb{E}[\bar\rho] \leq 1$ であること、および $\mathbb{E}[\bar\rho] \to e^{-d}$（$T \to \infty$ のとき）を示せ。重要度重み $W$ は $\mathbb{E}_{\pi_{\theta_{\textrm{old}}}}[W f] = \mathbb{E}_{\pi_\theta}[f]$ を応答のあらゆる関数 $f$ に対して満たす。$\bar\rho$ もこれを満たすか。
    1. GSPO は $\bar\rho$ を $[1 - 3 \cdot 10^{-4}, 1 + 4 \cdot 10^{-4}]$ にクリップし、比較対象の GRPO ベースラインはトークンごとの確率比を $[1 - 0.2, 1 + 0.27]$ にクリップする。(a) を用いて、系列レベルの許容帯が有効に働くためにはるかに狭くなければならない理由を説明せよ。

- **参照オッズ：**$\pi_{\textrm{ref}}$ のもとで、ヘッジのロジットは $-4$ であるのに対し通常の応答は $0$ である（$e^{-4} \approx 0.018$）

<!--en:8fb7e482-->
- **臨界しきい値（$\beta = 1/4$）：**解けないプロンプトにおいて、$\beta < 0.25$ ではヘッジが通常の各応答より高確率になり（確率質量の半分を占めるのは $\beta \approx 0.16$ 未満のみ）、**$\beta > 0.25$** では低確率になる

<!--en:4c677726-->
**正則化のトレードオフ：**$\beta = 0$ では、方策は満点の寛容スコア（$1.00$）を達成するが、これは確率質量の $100\%$ を `8*8` と `9*9` でヘッジに置くためである（ヘッジの平均確率 $0.50$）。$\beta$ を $0.3 > 0.25$ に引き上げるとヘッジは抑制される（$0.04$）一方、$\beta = 0.5$ まで過剰にペナルティを課すと厳密スコアまで引き下げてしまう（$0.50$ から約 $0.25$ へ低下）。

- **非対称クリッピング（DAPO の `Clip-Higher`、Yu et al.、2025 年）：**許容帯を $[0.80, 1.28]$ に広げ、高アドバンテージな低頻度推論トークンがエントロピー崩壊を起こさず速く成長できるようにする

<!--en:bfa1b6a8-->
- 第 1 エポックではすべての確率比が $\rho = 1.00$ だが、最初の 1 ステップの直後には正解の確率比がすでに $1.50$（$> 1 + \epsilon_{\textrm{clip}}$）を超えて跳ね上がっており、PPO・GRPO のクリッピングはパラメータのステップ自体を抑えるのではなく、それ以上の勾配の寄与を止めるだけであることが確認できる

::: {.slide title="k3 KL 推定量とその順方向 KL 勾配"}

<!--en:ee041448-->
[KL 損失の注意点]{.kicker}

<!--en:fd565608-->
- **直接損失と報酬ペナルティの比較（Tang & Munos、2025 年）：**$h = \log(\pi_\theta/\pi_{\textrm{ref}})$ とおくと、$k_1 = h$ を直接微分した期待勾配は 0 になる一方、$k_2 = \frac{1}{2}h^2$（または $h$ の報酬への折り込み）は**逆方向 KL 勾配**を与える（ヘッジを $0.017$ に抑制）

<!--en:d6115dcc-->
- **$k_3 = e^{-h} + h - 1$ の順方向 KL の罠：**$k_3$ を直接微分すると**順方向 KL 勾配** $\nabla_\theta D_{\textrm{KL}}(\pi_{\textrm{ref}} \Vert \pi_\theta)$ が生じ、低頻度のヘッジが $0.500$ のまま抑制されない

<!--en:ba8778c7-->
::: {.slide title="直接選好最適化：傾斜関係の逆算"}

<!--en:0322729a-->
[オフライン選好学習]{.kicker}

<!--en:5e2c69d0-->
- **分配関数の相殺（Rafailov et al.、2023 年）：**$r(x, y)$ を Bradley–Terry の報酬差 $r(x, y_w) - r(x, y_l)$ に代入すると、$\beta \log Z(x)$ が完全に相殺される

<!--en:1f901682-->
- **オフライン二値交差エントロピー：**$\pi_\theta$ を記録済みの選好ペア $(y_w \succ y_l)$ 上で直接訓練し、別個の報酬モデルやオンラインロールアウトを必要としない

::: {.slide title="理解度チェック：トークンの信頼割り当て・クリッピング・ツール"}

<!--en:929b7671-->
[理解度の確認]{.kicker}

<!--en:c9c37df1-->
実用的な 3 つの LLM 事後学習シナリオで理解度を確認しよう。

<!--en:7c467c63-->
1. **誤ったプレフィックス上のトークンアドバンテージ：**2 桁の `3*4 = 12` タスク（一様方策、$V(x) = 0.01, V(x, 1) = 0.1, V(x, 5) = 0$）において、トークンアドバンテージ $A(s_1, 5)$ と $A(s_2, 2)$ は、誤答 `52` において応答重み $r - V(x)$ と比べてどうなるか。

<!--en:d7bb1cee-->
2. **クリッピング後のソフトマックス結合：**$\epsilon_{\textrm{clip}} = 0.2$ の GRPO において、正解の応答が $\hat{A} = +2.6$、確率比 $\rho = 1.9 > 1.2$ を持ち、誤答が $\hat{A} = -0.4$、$\rho = 0.9 \in [0.8, 1.2]$ を持つとする。次のエポックでも正解の応答の確率はさらに増加しうるか。

<!--en:557b98b6-->
**解答：**

<!--en:d62df1c8-->
1. 応答重みは **$-0.01$ を両方の桁に**与える（一の位の `2` まで不当に罰する）。一方、トークンアドバンテージは **$A(s_1, 5) = -0.01$** および **$A(s_2, 2) = 0 - 0 = 0.00$** を与える（`5` を選んだ時点で失敗が確定していたことを反映する）。

<!--en:1bc91bb3-->
2. **増加しうる。**正解の応答自身のクリップされた項は勾配が 0 になるが、クリップされていない誤答が自身のロジットを*押し下げる*ため、共有されたソフトマックスの分母を通じて正解の応答の確率が増加する。

<!--en:a11c69e0-->
::: {.slide title="理解度チェック：トークンの信頼割り当て・クリッピング・ツール（続き）"}

<!--en:929b7671-2-->
[理解度の確認]{.kicker}

<!--en:c4b54238-->
3. **外部ツール出力のマスク処理：**エージェント型 LLM がクエリ $y^{(1)}$ を出力し、外部の Python インタプリタ出力 $o \sim P_{\textrm{tool}}(\cdot \mid x, y^{(1)})$ を受け取って最終回答 $y^{(2)}$ を出力するとき、なぜ $o$ のトークンを $\sum_t \nabla_\theta \log \pi_\theta(a_t \mid s_t)$ からマスクして除外しなければならないのか。

<!--en:23db34b8-->
**解答：**

<!--en:1b6b6468-->
3. ツールの遷移 $P_{\textrm{tool}}(o \mid x, y^{(1)})$ は $\theta$ に依存せず軌跡の確率比で相殺される。$\log \pi_\theta(o \mid x, y^{(1)})$ を微分すると $\mathbb{E}[\nabla \log \pi] = 0$ が破れ、ツール出力をハルシネーションするようモデルにバイアスをかけてしまう。
