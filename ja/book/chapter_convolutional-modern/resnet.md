# 残差ネットワーク

<!--en:d871a8ba-->
ImageNet においてはここまで、AlexNet の 8 層から GoogLeNet の 22 層に至るまで、ネットワークを深くすることは一貫して高い正解率を意味しており、バッチ正規化（:numref:`sec_batch_norm`）によって深さをさらに拡大するうえでの残りの障壁も取り除かれたかのように見えた。当然ながら、さらに多くの層を積み重ねれば、悪くとも過学習が始まるまでは訓練誤差が下がり続けると予想されるだろう。ところが、:citet:`He.Zhang.Ren.ea.2016` がバッチ正規化と ReLU を備えた VGG 風の*プレーン*な畳み込みの積層を深さを増しながら訓練してこの直感を検証したところ、まったく逆の結果が明らかになった。CIFAR-10 では、56 層のプレーンネットワークが 20 層のネットワークよりも大幅に高い*訓練*誤差で訓練を終えたのである。訓練セットへの当てはまりさえ悪化しているため、この*劣化問題*（degradation problem）は過学習ではなく、最適化の失敗である。この謎は深刻だ。原理的には、56 層のネットワークは 20 層の解をそのままコピーし、残りの 36 層にわたって恒等写像（identity mapping）として振る舞うだけで、少なくとも同じくらい低い訓練損失を保証できるはずである。なぜ SGD はそのような解を見つけられないのか、そして見つけられるようにするには基本ブロックをどう再設計すればよいのだろうか。

<!--en:9a2a4300-->
*残差ネットワーク*（residual network、ResNet）は、拍子抜けするほど単純な再パラメータ化（reparameterization）によってこの逆説を解決する。各ブロックに出力変換全体をゼロから学習させる代わりに、残差ブロック（residual block）は学習した補正項を入力に加算する。そのため、この補正項を 0 に近づけるだけで直ちに恒等写像が復元される。たった 1 本のこのショートカットが前例のない深さを可能にした。ImageNet では、34 層のプレーンネットワークが 18 層のモデルに遅れをとったのに対し、34 層の ResNet は 18 層の ResNet を 3 パーセントポイント近く上回り、152 層の ResNet が 2015 年の ImageNet コンペティションで優勝した。

<!--en:d3cad837-->
本節ではまず、入れ子の関数クラスを通じて深さを捉え直し、残差ブロックを設計する。次に、Fashion-MNIST 上で 20 層と 56 層のプレーンネットワークおよび残差ネットワークを並べて訓練することで劣化現象を直接再現し、劣化が現れては消える様子を目の当たりにする。続いて ResNet-18 を組み立てて訓練し、最後に影響力の大きい 2 つの後継モデルを取り上げる。すなわち、グループ畳み込み（grouped convolution）を用いて同等のコストでブロックの幅を広げる *ResNeXt* と、特徴マップを加算するのではなく連結する *DenseNet* である。

## 関数クラスと深さ

<!--en:2398692e-->
あるアーキテクチャの*関数クラス*（function class）$\mathcal{F}$、すなわちパラメータを変化させたときに達成可能な入出力写像の集合を考えよう。より大きなアーキテクチャ $\mathcal{F}'$ が、$\mathcal{F}$ 内の最良の解と少なくとも同じくらい低い訓練損失をもつ解を必ず含むのはどのようなときか。それは、関数クラスが*入れ子*（nested）になっており、$\mathcal{F} \subseteq \mathcal{F}'$（:numref:`fig_functionclasses`）を満たすときである。もし $\mathcal{F} \not\subseteq \mathcal{F}'$ であれば、クラスを大きくしても目標の関数 $f^*$ からかえって遠ざかることさえある。

<!--en:7724569d-->
![次第に大きくなる関数クラス。左は入れ子になっていない場合であり、大きなクラスが小さなクラスの関数を含むとは限らず、目標 $f^*$ に近づくとも限らない。右は各クラスが前のクラスをすべて含んでいるため、クラスが大きくなるにつれて利用可能な最良の関数は改善する一方である。](../img/functionclasses.svg)

<!--en:9205c011-->
追加した層が恒等写像 $f(\mathbf{x}) = \mathbf{x}$ を表現できる限り、層を追加することで関数クラスは入れ子になる。プレーンブロック $\mathbf{x} \mapsto \textrm{ReLU}(\textrm{BN}(\mathbf{W}\mathbf{x} + \mathbf{b}))$ は非負の入力に対して恒等写像を表現*できる*ため、プレーンネットワークはすでに :numref:`fig_functionclasses` の右パネルに示した入れ子の状況にある。つまり、その劣化は表現能力の不足ではなく最適化の失敗であり、SGD が何十もの非線形層にわたって恒等写像を近似するのに苦戦しているのである。残差ブロックは層を再パラメータ化し、残差分岐の重みがゼロになる原点 $g(\mathbf{x}) = 0$ に恒等写像が位置するようにする。

<!--en:413d44c4-->
## 残差ブロック

<!--en:fc8e39f3-->
目標の写像 $f(\mathbf{x})$ を直接学習する代わりに、残差ブロック（:numref:`fig_residual_block`）は*残差*（residual）$g(\mathbf{x}) = f(\mathbf{x}) - \mathbf{x}$ を学習し、*ショートカット*（または*スキップ*）接続を通じて入力を足し戻すことで $\mathbf{x} + g(\mathbf{x})$ を出力する。このブロックを恒等写像にするには、$g$ の最終層をゼロにするだけでよい。

<!--en:9c8f5f4b-->
![通常のブロック（左）は写像 $f(\mathbf{x})$ を直接学習しなければならない。残差ブロック（右）は残差写像 $g(\mathbf{x}) = f(\mathbf{x}) - \mathbf{x}$ を学習して入力を足し戻すため、恒等写像 $f(\mathbf{x}) = \mathbf{x}$ は $g(\mathbf{x}) = 0$ に対応する。](../img/arch-residual-concept.svg)

<!--en:b6ceb837-->
ショートカットは勾配の伝わり方も変える。積み重ねた 2 つのブロック $\mathbf{x}_1 = \mathbf{x}_0 + g_1(\mathbf{x}_0)$ と $\mathbf{x}_2 = \mathbf{x}_1 + g_2(\mathbf{x}_1)$ に対して、ヤコビ行列 $\partial \mathbf{x}_2 / \partial \mathbf{x}_0 = (\mathbf{I} + \partial g_2 / \partial \mathbf{x}_1)(\mathbf{I} + \partial g_1 / \partial \mathbf{x}_0)$ を展開すると単位行列 $\mathbf{I}$ と分岐項の和になるため、損失の勾配は途中のすべての重み行列との積を経ることなく初期のブロックに到達する（連続時間の観点からは、$\mathbf{x}_{l+1} = \mathbf{x}_l + g_l(\mathbf{x}_l)$ は常微分方程式（ODE）$\dot{\mathbf{x}} = g(\mathbf{x}, t)$ の単位ステップのオイラー離散化にあたる。:numref:`sec_mdl-neural-odes-cnf` を参照）。

<!--en:9d828a45-->
プレーンネットワークが劣化するのは勾配が消失するためだと結論づけたくなるかもしれない。しかしそうではない。:citet:`He.Zhang.Ren.ea.2016` は、バッチ正規化を施したプレーンネットワークがどの深さでも健全な勾配ノルムを維持していることを確認した。破綻の原因はより微妙であり、その後の研究によって 2 つの相補的な説明が与えられている。深いプレーンネットワークでは、深さが増すにつれて近傍の入力における勾配の相関が失われて白色雑音に近づき、SGD が従うべき一貫した方向を見失うのに対し、ショートカットがあると相関の減衰ははるかに緩やかになる :cite:`Balduzzi.Frean.Leary.ea.2017`。また重みの側から見ると、深いプレーンネットワークの損失ランドスケープは粗くカオス的であるのに対し、ショートカットは最小点の周囲でそれを滑らかに保つ :cite:`Li.Xu.Taylor.ea.2018`。上のヤコビ行列はその理由を示唆している。$L$ 個のブロックにわたって展開すると、因子 $\mathbf{I} + \partial g_l / \partial \mathbf{x}_{l-1}$ の積は $2^L$ 通りの経路にわたる和となり、勾配の大半は短い経路を通って流れるため、ResNet は比較的浅いネットワークのアンサンブルのように訓練される :cite:`Veit.Wilber.Belongie.2016`。このようなアンサンブルから 1 つのブロックを取り除いてもほとんど悪影響はなく、:numref:`sec_training_recipes` で扱う確率的深さ（stochastic depth）はこの性質を正則化手法へと転用している。

<!--en:d7c8289b-->
具体的には、ResNet の基本的な `Residual` ブロックは、バイアスなしの 2 つの $3 \times 3$ 畳み込みをバッチ正規化および中間の ReLU とともに積み重ね、2 番目のバッチ正規化の出力にショートカット入力 $\mathbf{x}$ を加算し、最後に ReLU を適用する。2 番目のバッチ正規化で $\gamma = \beta = 0$ と設定すれば分岐の出力はゼロになり、非負の入力に対して $\textrm{ReLU}(\mathbf{x}) = \mathbf{x}$ が復元される。大規模訓練のレシピではこれを初期化に利用し、すべての残差分岐の最後の $\gamma$ を 0 から始めることで、最初のステップでは各ブロックを恒等写像とし、分岐が徐々に育っていく浅いネットワークとして深いネットワークの訓練を開始する :cite:`Goyal.Dollar.Girshick.ea.2017,He.Zhang.Zhang.ea.2019`。本節で扱うネットワークはデフォルトの $\gamma = 1$ でも十分に訓練できる浅さであるため、そのままにしておく。`use_1x1conv=True` または `strides != 1` によってチャネル幅や空間解像度（spatial resolution）が変化するときは、加算が適切に定義されるよう、ショートカット側にもストライドを合わせた $1 \times 1$ 畳み込みとバッチ正規化を適用する。

<!--en:6e7fd0da-->
NNX の層は構築時に入力チャネル数を必要とするため、JAX 版の `Residual` は引数 `in_channels`（デフォルトは `num_channels`）を受け取る。

<!--en:a886ef60-->
:numref:`fig_resnet_block` に両方の構成を示す。`use_1x1conv=True` を渡すか、1 より大きいストライドを設定すると、右側の射影ショートカットが有効になる。

<!--en:a7125e94-->
![ResNet ブロックの 2 つの変種。入出力の形状が一致するときは恒等ショートカットを用い（左）、形状が異なるときはショートカット上の $1 \times 1$ 畳み込みとバッチ正規化によってチャネル数と解像度を調整し、加算が定義されるようにする（右）。](../img/arch-resnet-block.svg)

<!--en:c74c34c3-->
出力の形状を確認してみよう。入出力のチャネル数が一致しストライドが 1 のとき、このブロックはテンソルの形状 `(4, 3, 6, 6)` をそのまま保つ。

<!--en:30a7a02f-->
`num_channels=6`、`use_1x1conv=True`、`strides=2` と設定すると、チャネル数が 2 倍になると同時に高さと幅がいずれも半分になる。これは、以下で構築する ResNet のステージ 2、3、4 の先頭に置かれるダウンサンプリングブロックそのものである。

## プレーンネットワークと残差ネットワークの比較

<!--en:ca806a63-->
Fashion-MNIST 上で劣化問題を直接再現し、残差ショートカットがそれを解消する様子を観察できるだろうか。条件を揃えた明確な対照実験を行うため、ショートカット接続の有無*のみ*が異なる 2 つのネットワーク族を構築する。:citet:`He.Zhang.Ren.ea.2016` による CIFAR-10 向けの設計を Fashion-MNIST 本来の $28 \times 28$ 画像に適合させることで、深いモデルでも高速に訓練できる。*プレーンブロック*は、迂回経路の加算を除けば `Residual` と層単位で同一であり、2 つの $3 \times 3$ 畳み込みのそれぞれにバッチ正規化と ReLU が続く構成をとる。

<!--en:cac4eb24-->
各ネットワークは、16 チャネルの $3 \times 3$ 畳み込み、バッチ正規化、ReLU から始まり、チャネル数が 16、32、64 である $n$ ブロックずつの 3 つのステージが続き（ステージ 2 と 3 の最初のブロックはストライド 2 でダウンサンプリングする）、最後はグローバル平均プーリングと線形分類器で終わる。ステム、ブロックあたり 2 つの畳み込み、および線形のヘッドを数えると合計 $6n + 2$ 層になり、$n = 3$ では 20 層、$n = 9$ では 56 層となる。`plain_block` または `Residual` のいずれかを `block` として渡すことで、条件を揃えた対となるモデルを構築できる。これまでと同様に、すべての重みを He 初期化（:numref:`subsec_he_init`）で初期化し、`d2l.cosine_warmup`（:numref:`sec_alexnet`）を用いてピーク学習率 0.1 で訓練する。この学習率は :numref:`sec_blocks` では正規化なしのネットワークを不安定化させたが、ここではすべての畳み込みの後にバッチ正規化（:numref:`sec_batch_norm`）があるため滑らかに訓練が進む。

<!--en:40b85248-->
`init.MSRAPrelu('in', 0)` は MXNet における He 初期化の名称である。このネットワークは `HybridBlock` から構築されており、`hybridize()` によって単一の計算グラフにコンパイルされるため、MXNet は演算子を 1 つずつ実行する場合よりも数倍高速に実行する。

<!--en:18c9df80-->
:numref:`sec_lenet` の LeNet と同様に、最初のミニバッチによって遅延初期化層の形状が確定した時点で、Trainer がモデルの `weight_init` を呼び出す。これにより He 初期化（`kaiming_normal_`）が、`Residual` ブロックの内部も含むすべての畳み込み層と全結合層に適用される。

<!--en:b98f6e97-->
`VarianceScaling(2.0, 'fan_in', 'untruncated_normal')` が He 初期化にあたる。シードを指定しない Keras の初期化器は 1 つのインスタンスを共有すると同じ値を繰り返すため、層ごとに個別のインスタンスを渡しており、`Residual` も内部で同様の処理をしている。

<!--en:4da82e81-->
NNX の層は構築時に重みをサンプリングするため、`Residual` の内部も含むすべての層が He 初期化（`variance_scaling(2.0, 'fan_in', 'normal')`）を `kernel_init` として受け取る。

<!--en:26832912-->
4 つの構成すべて（20 層および 56 層のプレーンネットワークと残差ネットワーク）をバッチサイズ 128 で 5 エポック訓練し、訓練履歴をすべて記録する。

<!--en:dd7231ea-->
4 本すべての訓練損失の曲線を対数スケールの y 軸上に重ねてプロットしてみよう（青が 20 層、赤が 56 層であり、破線がプレーンネットワーク、実線が残差ネットワークを表す）。

<!--en:5bed84df-->
また、20 層と 56 層の 4 つの構成すべてについて、最終エポックの `train_loss` と `val_acc` を `history` から確認する。

<!--en:734feddf-->
プレーンネットワークには劣化現象が紛れもなく現れている。56 層のプレーンネットワークは最終的な訓練損失が 0.25〜0.30 前後と、20 層のプレーンネットワークの約 0.20 よりも高く、すべてのエポックにおいて浅いモデルの曲線よりも厳密に*上*に位置している。訓練損失そのものが悪化しているため、過学習の可能性は除外される。一方、残差ショートカットを有効にすると順序は完全に逆転する。56 層の残差ネットワークは訓練損失が約 0.15〜0.17 まで下がり、20 層の両ネットワーク（ショートカットの有無にかかわらず 0.19 付近で終了）を上回る。20 層ではショートカットの影響はほとんど見られないが、56 層では追加の 36 層が最適化を妨げるか改善するかをショートカットが決定づけている。これら 4 回の実験で変えたのは深さとショートカット接続だけであるため、この差がショートカットによるものであることは明白だ。検証正解率にも同じ傾向がより緩やかに現れており、5 エポック後の時点で 56 層のプレーンネットワークが 88〜90% と遅れをとる一方、残りの 3 つは 90.5〜91.5% の狭い範囲に集まっている。

## ResNet-18

<!--en:d43a6c8c-->
### ステム、ステージ、ヘッド

<!--en:35145558-->
本格的な ImageNet スケールにおいて、ResNet は GoogLeNet（:numref:`sec_googlenet`）が確立したステム・ボディ・ヘッドのアーキテクチャを採用している。その*ステム*は、ストライド 2 で 64 チャネルの $7 \times 7$ 畳み込み、バッチ正規化、ReLU、およびストライド 2 の $3 \times 3$ 最大プーリングから始まり、空間次元をいきなり 4 分の 1 に縮小する。以下の `ResNet.stem` はこの入り口のモジュールを構築する。

<!--en:77b9068d-->
*ボディ*は 4 つの*ステージ*からなり、各ステージは一定のチャネル幅で `num_residuals` 個の残差ブロックを積み重ねる。ステムがすでに入力を 4 分の 1 にダウンサンプリングしているため、ステージ 1 は解像度と 64 チャネルをそのまま維持し、それ以降の各ステージは先頭にストライド 2 の射影ブロックを置いて高さと幅を半分にしつつチャネル数を 2 倍にする。`stage` メソッドはそのようなステージを 1 つ構築する。

<!--en:8345e519-->
モデルを締めくくる*ヘッド*は NiN や GoogLeNet に倣い、グローバル平均プーリングに単一の線形分類層が続く構成をとる。`VGG` と同様に、引数 `arch` で各ステージの `(num_residuals, num_channels)` を指定し、すべての畳み込み層と線形層の重みには He 初期化を用い、出力層にある唯一のバイアスは 0 で初期化する。

<!--en:4b5dad34-->
4 つの各ステージに 2 つずつ残差ブロックを配置すると *ResNet-18* になる。4 ステージ $\times$ 4 つの $3 \times 3$ 畳み込み（ショートカットの $1 \times 1$ 射影は除く）に、ステムの $7 \times 7$ 畳み込みと最終の線形層を加えると、パラメータをもつ層は合計 18 層になる。ResNet-34 はステージごとに `(3, 4, 6, 3)` 個のブロックを用い、さらに深いモデル（ResNet-50、ResNet-101、ResNet-152）では 3 層の*ボトルネック*ブロック（$1 \times 1 \to 3 \times 3 \to 1 \times 1$）に置き換える。これは後述する ResNeXt ブロックでグループ数を 1 とした場合に一致する。:numref:`fig_resnet18` に ResNet-18 の全体構造を示す。

<!--en:dbec9ebe-->
![ResNet-18 の構造。$7\times 7$ 畳み込みのステム、残差ブロックを 2 つずつもつ 4 つのステージ（ステージ 2、3、4 の最初のブロックで解像度を半分にしチャネル数を 2 倍にする）、およびグローバル平均プーリングと 1 つの全結合層からなるヘッドで構成される。形状は $96 \times 96$ 入力に対するものである。](../img/arch-resnet18.svg)

<!--en:6aafeea6-->
1 チャネルの $96 \times 96$ 画像を ResNet-18 に通し、グローバル平均プーリングに向かって解像度が段階的に下がりチャネル幅が広がっていく際のテンソル形状をたどってみよう。

### 訓練

<!--en:ce91f088-->
`ResNet18` を訓練するため、まず `DeepNet` のコサインウォームアップ付き SGD スケジュールを `configure_optimizers` によって設定する。

<!--en:b890539e-->
それでは、`ResNet18` を $96 \times 96$ にリサイズした Fashion-MNIST 上で、バッチサイズ 128、ピーク学習率 `lr=0.1` で 10 エポック訓練しよう。

<!--en:9974eeb8-->
`trainer.history['val_acc']` の最後の要素を読み取ることで、10 エポックのコサインスケジュール終了時点での検証正解率が得られる。

<!--en:c451ee49-->
10 エポック後、ResNet-18 は約 93% の検証正解率に達し（最後の 3 エポックでの変動は 1 ポイント未満）、:numref:`sec_blocks` の 4 分の 1 幅の VGG と同等の精度を、わずか 4 分の 1 のパラメータ数、かつ $96 \times 96$ ピクセル（$224 \times 224$ ピクセルではなく）の入力で達成している。もっとも、アーキテクチャ、正規化、入力解像度がすべて同時に変化している異なるモデル族間の単一の比較を過大解釈しないよう注意すべきである。残差接続（residual connection）の真価を示す明確な証拠は、:numref:`subsec_plain_residual` で行った 20 層対 56 層の対照実験にある。

<!--en:2d188fba-->
また、過学習の典型的な兆候にも注目しよう。ResNet-18 は訓練損失を 0.01 未満まで引き下げる一方、検証損失は最初の数エポック以降 0.27 前後で頭打ちになる。60,000 枚のグレースケール衣類画像に対して 1,120 万個のパラメータを訓練しているため、訓練セットの丸暗記は容易である。この汎化ギャップ（generalization gap）を縮めるにはより強力なデータ拡張（data augmentation）と正則化が必要であり、これについては :numref:`sec_training_recipes` で体系的に取り組む。

<!--en:6792a7b4-->
## ResNeXt と DenseNet

<!--en:b73dedb5-->
残差接続は、ブロックが学習した変換に入力を加算するという形で、ブロックが入力を*どのように*先へ伝えるかを規定する。代表的な 2 つの後継アーキテクチャは、ショートカット配線という思想を受け継ぎながらブロック自体を改良している。*ResNeXt* はブロック内部の畳み込みを再設計して計算量を増やさずにチャネル幅を広げ、*DenseNet* は加算型のショートカットをチャネルの連結（concatenation）に置き換える。ResNeXt ブロックについては、:numref:`sec_cnn-design` で体系的なネットワーク設計空間を探究する際に再び取り上げる。

<!--en:6c893887-->
### ResNeXt

<!--en:a173d36b-->
幅広い層はより豊かな表現を学習できるが、$c_\textrm{i}$ チャネルを $c_\textrm{o}$ チャネルに写す標準的な畳み込みのコストは $c_\textrm{i} c_\textrm{o}$ に比例して増大するため（:numref:`sec_channels`）、幅を 2 倍にすると重みと演算量の双方が 4 倍になる。*ResNeXt* :cite:`Xie.Girshick.Dollar.ea.2017` は、GoogLeNet の多分岐 Inception の発想（:numref:`sec_googlenet`）を、すべての分岐がまったく同じトポロジーをもつ完全に均一な構造へと発展させたものである。

<!--en:8c7b6b5b-->
具体的には、*グループ畳み込み*は $c_\textrm{i}$ 個の入力チャネルを互いに素な $g$ 個のグループ（各 $c_\textrm{i}/g$ チャネル）に分割し、各グループを独立に畳み込んで $c_\textrm{o}/g$ 個の出力チャネルを生成する（ただし $g$ は $c_\textrm{i}$ と $c_\textrm{o}$ の両方を割り切ると仮定する）。各グループに必要なカーネルのサイズは $(c_\textrm{i}/g) \times (c_\textrm{o}/g) \times k \times k$ であり、全 $g$ グループにわたる総パラメータ数と積和演算（multiply-add）の回数は $g$ 分の 1 に削減され、$c_\textrm{i} c_\textrm{o} k^2$ から $c_\textrm{i} c_\textrm{o} k^2 / g$ へと減る（実際には、メモリアクセス量が演算量と同じ割合では減らないため、実時間での高速化は通常 $g$ 倍未満にとどまる。この違いについては :numref:`sec_efficient_cnns` で詳しく調べる）。歴史的には、グループ畳み込みは AlexNet :cite:`Krizhevsky.Sutskever.Hinton.2012` で初めて導入され、2 基の GPU に収めるために 5 つの畳み込み層のうち 3 つを 2 グループに分割するのに使われた。

<!--en:0cdd3ac3-->
独立したグループ同士はそれ自体では情報を交換できないため、ResNeXt ブロック（:numref:`fig_resnext_block`）はグループ化した $3 \times 3$ 畳み込みを 2 つの密な $1 \times 1$ 畳み込みで挟み込む。1 つ目の畳み込みが $c$ 個の入力チャネルを $b$ 個の*ボトルネック*チャネルへと射影し、2 つ目の畳み込みが再び $c$ チャネルへ射影して全グループ間の情報を混合する。2 つの $1 \times 1$ 層は $2cb$ 個の重みを用い、グループ化した $3 \times 3$ 層は $9b^2/g$ 個の重みを用いる。ダウンサンプリング時には、ストライド 2 の処理を $3 \times 3$ 畳み込みに持たせ（最初の $1 \times 1$ 射影ではなく）、ショートカットは `Residual` と同じ形にする。

<!--en:d785bcfb-->
「同等のコストでより幅広く」が数値的に何を意味するかを見るため、標準的な ResNet-50 のボトルネックブロック（$c = 256$、$b = 64$、$g = 1$）で使用される $2 \cdot 256 \cdot 64 + 9 \cdot 64^2 = 69{,}632$ 個の重みと、:numref:`fig_resnext_block` に示す ResNeXt ブロック（$b = 128$、$g = 32$）で使用される $2 \cdot 256 \cdot 128 + 9 \cdot 128^2/32 = 70{,}144$ 個の重みを比較してみよう。重みの増加を 1% 未満に抑えながら、内部のボトルネック幅が 2 倍になっている。ImageNet では、この単純なトレードオフによって ResNet-50 の top-1 誤差が 23.9% から 22.2% へと低下する :cite:`Xie.Girshick.Dollar.ea.2017`。

<!--en:b595fbd7-->
![ResNeXt ブロック。$3 \times 3$ のグループ畳み込み（グループ数 $\mathit{g}$）を、グループ間で情報を混合する 2 つの $1 \times 1$ 畳み込みで挟む。図のブロックはチャネル数 $\mathit{c} = 256$、ボトルネックチャネル数 $\mathit{b} = 128$、4 チャネルずつのグループ数 $\mathit{g} = 32$ である。](../img/arch-resnext-block.svg)

<!--en:f08337d9-->
以下の `ResNeXtBlock` は、出力幅 `num_channels`（$c$）、グループ数 `groups`（$g$）、およびボトルネック比 `bot_mul`（$b/c$）を受け取る。`Residual` と同様に、`strides=2` を渡すと高さと幅が半分になり、ショートカットの $1 \times 1$ 射影が自動的に有効になる。

<!--en:ce969008-->
32 チャネル、16 グループ、`bot_mul=1` のブロックが入力テンソルの形状を保つことを確認しよう。

<!--en:43536b51-->
### DenseNet

<!--en:307785f8-->
残差ブロックが出力を入力に加算し（$\mathbf{x}_k = \mathbf{x}_{k-1} + g_k(\mathbf{x}_{k-1})$）、チャネル幅を一定に保ちながら古い特徴と新しい特徴を混ぜ合わせるのに対し、*DenseNet*（dense convolutional network、密結合畳み込みネットワーク）:cite:`Huang.Liu.Van-Der-Maaten.ea.2017` は各層の出力を入力に対してチャネル次元に沿って*連結*する。

<!--en:88f97c2c-->
ここで、$[\cdot, \cdot]$ はチャネル方向の連結を表す。いかなる情報も上書きされることはない。$\mathbf{x}_k$ は元のブロック入力と先行する $k$ 個すべての層の出力をそのまま保持するため、ブロック内のすべての層がそれ以前のすべての層と直接接続される。:numref:`fig_densenet_block` に 2 層の密ブロック（dense block）を示す。

<!--en:0759dfd9-->
![2 層で成長率が 32 の密ブロック。各層が 32 個の出力チャネルを入力に追加するため、64 チャネルの入力は 96 チャネル、次いで 128 チャネルへと増加し、すべての層がそれ以前の全層の出力を参照する。](../img/arch-densenet-block.svg)

<!--en:faec3e00-->
密ブロックの内部では、各畳み込みはプレアクティベーションの順序（バッチ正規化 $\to$ ReLU $\to$ バイアスなしの畳み込み）を採用する。この順序を ResNet に適用した場合については後述の演習問題で調べる。各層が新たに追加するチャネル数（:numref:`fig_densenet_block` では 32）は*成長率*（growth rate）と呼ばれる。どの密ブロックの内部でもチャネル幅が線形に増加するため、DenseNet は連続するブロックの間に*遷移層*（transition layer）を挿入し、$1 \times 1$ 畳み込みでチャネル数を圧縮するとともにストライド 2 の平均プーリングで高さと幅を半分にする。完全な DenseNet は遷移層を挟んで 4 つの密ブロックを積み重ねており、ResNet-18 の 4 ステージ構成と対応している（その構築と訓練の手順は :exref:`ex_resnet-densenet` で扱う）。

<!--en:4ef70d83-->
DenseNet はより少ないパラメータ数で ResNet に匹敵する ImageNet 正解率を達成し、著者らはその要因を徹底した特徴の再利用に帰した。しかし実用上の欠点は活性化メモリ（activation memory）にある。*固有の*特徴マップの数はブロックの深さに対して線形にしか増えないにもかかわらず、素朴な実装では層ごとにより幅の広い新たな連結テンソル（およびその正規化後のコピー）を確保して誤差逆伝播法のためにキャッシュするため、逆伝播の際に中間テンソルを再計算する特殊な実装を用いない限り、メモリ使用量が深さの*二乗*に比例して増大してしまう :cite:`pleiss2017memory`。加算型の残差ショートカットはこのメモリオーバーヘッドを完全に回避できる。これが、加算型のスキップ接続（skip connection）が深層学習全般で普遍的な標準となった主要な理由の 1 つである。

<!--en:c29e608b-->
それでもなお、連結型のスキップ接続は 1 つの主要なアーキテクチャ族において中心的な役割を担い続けている。それが画像セグメンテーション（image segmentation）向けの *U-Net* :cite:`Ronneberger.Fischer.Brox.2015` であり、画像を段階的にダウンサンプリングしたのち元の解像度までアップサンプリングし、アップサンプリングされた各特徴マップをエンコーダ経路の対応する高解像度マップと連結する。連結は層ごとではなく空間スケールごとに 1 回しか行われないため、メモリ消費は控えめに抑えられる。この同じ U-Net バックボーンはのちに現代の画像拡散モデル（diffusion model、:numref:`sec_diffusion-images`）の原動力ともなった。

<!--en:30ac03ff-->
## まとめ

<!--en:6208eea3-->
驚くべきことに、バッチ正規化を施したプレーンネットワークでは、深いアーキテクチャの関数クラスが浅いモデルの関数クラスを厳密に含んでいるにもかかわらず、層を積み増すことで浅いモデルよりも訓練損失が*増加*してしまうことがある。残差ブロックは加算的な補正 $\mathbf{x} + g(\mathbf{x})$ を学習することでこの劣化問題を解決する。これにより恒等写像が $g = 0$ に位置するようになり、深さが増してもショートカットが勾配の一貫性と損失ランドスケープの滑らかさを保つ。Fashion-MNIST では、56 層のプレーンネットワークは 20 層のモデルより訓練結果が悪化するのに対し、残差ショートカットを導入すると 56 層のモデルの方が良好に訓練される。残差ブロックをバッチ正規化とともに 4 つのステージに配置することで ResNet-18（Fashion-MNIST で 10 エポック後に検証正解率約 93%）が得られ、150 層を超える深さへも無理なくスケールする。ResNeXt はグループ畳み込みによって同等のコストでボトルネックブロックの幅を広げ、DenseNet はメモリコストの増加と引き換えに加算型ショートカットを特徴の連結へと置き換える。以来、残差接続は :numref:`chap_transformers` の Transformer をはじめ、現代のほぼすべてのアーキテクチャに不可欠な基盤となっている。

## 演習問題

<!--en:1cfa2051-->
1. **Inception ブロックと残差ブロックの比較。**GoogLeNet の `arch`（:numref:`sec_googlenet`）において、中間ステージの 2 番目のブロックは分岐幅 $c_1 = 160$、$c_2 = (112, 224)$、$c_3 = (24, 64)$、$c_4 = 64$ をもち、512 個の入力チャネルを 512 個の出力チャネルへ写像する。これを恒等ショートカット付きの 512 チャネル `Residual` ブロックと比較せよ。
    1. 両ブロックの畳み込みの重み数と出力ピクセルあたりの積和演算回数を数えよ（バイアスとバッチ正規化のパラメータは無視してよい）。
    1. 分岐の出力がゼロである `Residual` ブロックは、非負の入力（ブロックが ReLU の直後に続く場合は常に成り立つ）に対して恒等写像を計算する。訓練モードと予測モードにおいて `bn2` が何を出力するかを `conv2` をゼロにした場合について確認し、両モードでブロックを厳密な恒等写像にする `bn2` のパラメータを述べよ。また、4 分岐の Inception ブロックが非負の入力に対して恒等写像を計算するようなパラメータの選び方は存在するか。

<!--en:3d66c141-->
1. **プレアクティベーションの順序。**:citet:`He.Zhang.Ren.ea.2016*1` はバッチ正規化と ReLU を各畳み込みの*前*に移し（$\textrm{BN} \to \textrm{ReLU} \to \textrm{Conv}$）、加算後の ReLU を取り除くことで、各ブロックが手つかずの恒等ハイウェイを保ったまま $\mathbf{x}_k = \mathbf{x}_{k-1} + g_k(\mathbf{x}_{k-1})$ を計算するようにした（:numref:`sec_densenet` の DenseNet ブロック内部と同じ順序である）。
    1. 積み重ねた $K$ 個のプレアクティベーションブロックについて、$\mathbf{x}_K$ を $\mathbf{x}_0$ と各分岐出力を用いて表し、ヤコビ行列 $\partial \mathbf{x}_K / \partial \mathbf{x}_0$ が加算項として厳密な単位行列 $\mathbf{I}$ を含むことを示せ。
    1. 標準的なポストアクティベーション型の `Residual` ブロック（それぞれ加算後に ReLU を適用する）を $K$ 個積み重ねた場合、$\mathbf{I}$ に代わって $\partial \mathbf{x}_K / \partial \mathbf{x}_0$ に現れる因子は何か。

<!--en:75ba313b-->
1. [code] **プレーンネットワークの勾配。** ● :citet:`He.Zhang.Ren.ea.2016` は、バッチ正規化を施したプレーンネットワークが深さとともに劣化するにもかかわらず勾配消失を起こしていないことを指摘した。:numref:`subsec_plain_residual` の 20 層および 56 層の 4 つのネットワークでこのことを確認せよ。
    1. 初期化直後と 1 エポックの訓練後に、1 つのミニバッチ上で損失の勾配を計算し、4 つのネットワークすべてについて各畳み込み層の重み勾配のフロベニウスノルムを層のインデックスに対してプロットせよ。56 層のプレーンネットワークの勾配は入力層に向かうにつれて消失しているか。
    1. 56 層のプレーンネットワークを 5 エポックではなく 20 エポック訓練せよ。その訓練損失は 20 層のプレーンネットワークに追いつくか。

<!--en:c8b7e14f-->
1. [code] **ResNet-34 と ResNet-50 のボトルネック。** ● :citet:`He.Zhang.Ren.ea.2016` の表 1 は、ステージの深さとブロックの種類によって ResNet-18 から ResNet-152 までを定義している。
    1. ResNet-34（`arch=((3, 64), (4, 128), (6, 256), (3, 512))`）を `ResNet` を用いて構築し、そのパラメータ数を `ResNet18` と比較せよ。

ResNet-50 は 2 層の `Residual` ブロックを 3 層のボトルネックブロック（$1 \times 1$ で幅を $4\times$ 縮小し、$3 \times 3$ を経て、$1 \times 1$ で幅を復元する構造であり、`ResNeXtBlock` で `groups=1, bot_mul=0.25` としたもの）に置き換え、ステージ出力幅を $4\times$ 広い `(256, 512, 1024, 2048)` にする。幅 $4c$ の ResNet-50 ボトルネックブロック 1 個のパラメータ数と積和演算回数を幅 $c$ の ResNet-34 の `Residual` ブロック 1 個と比較し、続いて `stage` を `ResNet` のサブクラスでオーバーライドして ResNet-50 を構築し、総パラメータ数を確認せよ。

[code] **ResNet-D のダウンサンプリングショートカット。**ストライド 2 の `Residual` ブロックでは、ショートカットの $1 \times 1$ でストライド 2 の畳み込みは 4 つの空間位置のうち 1 つしかサンプリングせず、残りの 3 つを捨ててしまう。:citet:`He.Zhang.Zhang.ea.2019` はこれを、$2 \times 2$ でストライド 2 の平均プーリングに続けてストライド 1 の $1 \times 1$ 畳み込みとバッチ正規化を行う構成に置き換えている。この ResNet-D ショートカットを `Residual` のサブクラスとして実装し、出力の形状とパラメータ数が変わらないことを確認したうえで、Fashion-MNIST における 10 エポック訓練後の検証正解率を複数回の実行にわたって `ResNet18` と比較せよ。

::: {.slide title="入れ子の関数クラスによる単調改善の保証"}

<!--en:5e8a4952-->
[理論的枠組み]{.kicker}

<!--en:d926bdde-->
モデル族の系列 $\mathcal{F}_1, \mathcal{F}_2, \ldots, \mathcal{F}_K$ で目標写像 $f^*$ を近似することを考える

<!--en:148e4bc2-->
- **入れ子でないクラス（$\mathcal{F} \not\subseteq \mathcal{F}'$）：**既存の写像を保たずに層を拡張すると、クラス全体が $f^*$ から遠ざかる恐れがある

<!--en:e5cc70df-->
- **入れ子のクラス（$\mathcal{F} \subseteq \mathcal{F}'$）：**達成可能な最良の損失が深さによって悪化しないことを保証する
  $$\mathcal{F} \subseteq \mathcal{F}' \implies \min_{f \in \mathcal{F}'} L(f) \le \min_{f \in \mathcal{F}} L(f)$$

<!--en:87f897b9-->
- **最適化ギャップ：**プレーンな層 $\textrm{ReLU}(\textrm{BN}(\mathbf{W}\mathbf{x}))$ は $\mathbf{x}$ を $\mathbf{x} \ge 0$ 上で表現*できる*ため理論上は入れ子だが、恒等写像が扱いにくい内部の重み配置にあり SGD が到達できない

<!--en:6d68295f-->
::: {.slide title="残差ブロック：恒等写像への補正の学習"}

<!--en:836521cf-->
[残差ブロック]{.kicker}

<!--en:352c74d5-->
積み重ねたブロックに目的の写像 $f(\mathbf{x})$ を直接パラメータ化させる代わりに、残差ブロックは*残差*による補正 $g(\mathbf{x}) = f(\mathbf{x}) - \mathbf{x}$ を学習し、ショートカット接続で入力を足し戻す

<!--en:cba7621a-->
- **原点に位置する恒等写像（$g(\mathbf{x}) = \mathbf{0}$）：**
  $$f(\mathbf{x}) = \mathbf{x} + g(\mathbf{x})$$

<!--en:19a9f8bd-->
- **恒等写像への誘導が容易：**ブロックの変換を $\mathbf{x}$ にするには、残差分岐の重み（または最終バッチ正規化の $\gamma_2, \beta_2$）をゼロに近づけて $g$ を消すだけでよい

<!--en:f107f1ae-->
- **恒等写像まわりのプレコンディショニング：**$g(\mathbf{x}) \neq \mathbf{0}$ のときでも、$\mathbf{x}$ の周囲の小さな摂動的補正を学習する方が、恒等写像に近い座標変換全体をゼロから学習するよりはるかに条件がよい

<!--en:ede30e22-->
::: {.slide title="深さを貫く恒等勾配ハイウェイ"}

<!--en:45a1a20f-->
[逆伝播のヤコビ行列解析]{.kicker}

<!--en:958253b1-->
- **加算的な単位行列 $\mathbf{I}$：**$\mathbf{x}_L = \mathbf{x}_\ell + \sum g_k$ と展開でき、上流の勾配 $\partial L / \partial \mathbf{x}_L$ が途中の重み行列との積を経ずに初期の層 $\mathbf{x}_\ell$ へ直接届く

<!--en:dbc5ca70-->
::: {.slide title="恒等ショートカットと 1×1 射影ショートカット"}

<!--en:c92c7fa9-->
[ブロックのトポロジー]{.kicker}

<!--en:5d018d98-->
ResNet の基本的な `Residual` ブロックはバイアスなしの 2 つの $3\times 3$ 畳み込みとバッチ正規化を積み重ね、2 番目の ReLU の前でショートカットを加算し、次元が変わるときは $1\times 1$ 射影を用いる

<!--en:e249fb2e-->
- **恒等ショートカット（左、同一形状）：**$c_{\textrm{o}} = c_{\textrm{i}}$ かつストライド $s = 1$ のとき、$\mathbf{x}$ を**追加パラメータなし**でそのまま加算する

<!--en:d69c0764-->
- **射影ショートカット（右、ダウンサンプリング）：**$c_{\textrm{o}} \neq c_{\textrm{i}}$ またはストライド $s = 2$ のとき、ストライド $s$ の $1\times 1$ 畳み込みとバッチ正規化で $\mathbf{x}$ を射影し、空間サイズとチャネル幅を揃える

<!--en:878951c7-->
- **分岐ゼロ条件：**2 番目のバッチ正規化で $\gamma_2 = \beta_2 = 0$ とすると訓練時・評価時ともに残差分岐がゼロになり、$\textrm{ReLU}(\mathbf{x}) = \mathbf{x}$（$\mathbf{x} \ge 0$ のとき）が復元される

[ResNet-18 の構造]{.kicker}

<!--en:4d7d3831-->
本格的なスケールでは、ResNet は GoogLeNet のステム・ボディ・ヘッドのテンプレート内に 4 つの残差ステージを組み込む

<!--en:cb9e0c1b-->

<!--en:7402d91d-->

<!--en:f029ef7a-->
- **プーリング付きヘッド（重み層 1）：**グローバル平均プーリング + $512 \to 10$ の線形層（計 $1 + 16 + 1 = 18$ 層、**1,118 万パラメータ**）

::: {.slide title="ResNeXt：グループ畳み込みによるボトルネックの広幅化"}

<!--en:ce700238-->
[ResNeXt とカーディナリティ]{.kicker}

<!--en:fb7cd37a-->
チャネル幅を 2 倍にすると通常の密な畳み込みのコスト（$c_{\textrm{i}} c_{\textrm{o}} k^2$）は 4 倍になる。*ResNeXt*（Xie et al., 2017）は $3\times 3$ 畳み込みを $g$ 個の独立したグループ（*カーディナリティ*）に分割し、同等のコストで内部のボトルネック幅を広げる

<!--en:63b8636d-->
- **グループ化 $3\times 3$ による削減：**$b$ 個のボトルネックチャネルを $g$ 個のグループ（各 $b/g$ チャネル）に分割すると、$3\times 3$ の重みは $g$ 分の 1 に減り、$9b^2$ から $9(b/g)^2 \cdot g = 9b^2/g$ になる

<!--en:dbeabe0f-->
- **全結合的な $1\times 1$ 混合：**グループ化 $3\times 3$ 層を 2 つの密な $1\times 1$ 畳み込み（$c \to b$ と $b \to c$、重み数 $2cb$）で挟み、ブロックごとにグループ間で情報を交換する

<!--en:60e6ed72-->
- **同等コストでの広幅化：**ResNet-50（$c=256, b=64, g=1$）の重み数 $2(256)(64) + 9(64^2) = 69{,}632$ に対し、ResNeXt-50（$b=128, g=32$）はボトルネック幅を 2 倍の $128$ にしつつ重み数 $2(256)(128) + 9(128^2)/32 = 70{,}144$（+0.7%）に収め、ImageNet の top-1 誤差を **23.9% から 22.2%** に削減

::: {.slide title="DenseNet：連結と二乗オーダーの活性化メモリ"}

<!--en:f60f1971-->
[DenseNet とスキップ構造]{.kicker}

<!--en:8cd321fd-->
加算 $\mathbf{x}_k = \mathbf{x}_{k-1} + g_k(\mathbf{x}_{k-1})$ の代わりに、*DenseNet*（Huang et al., 2017）は各層の*成長率* $r$ チャネルの出力を先行するすべての特徴マップに連結する

<!--en:7394b097-->
- **明示的な特徴の再利用：**
  $$\mathbf{x}_k = [\mathbf{x}_{k-1},\; f_k(\mathbf{x}_{k-1})]$$
  $n$ 層を $c$ チャネル入力に適用するとテンソルは $c + n r$ チャネルになり、密ブロック間の遷移層（$1\times 1$ 畳み込み + $2\times 2$ 平均プーリング）が幅を圧縮する

<!--en:074c3fd7-->
- **実用上で加算型ショートカットが主流となった理由（メモリの落とし穴）：**素朴な DenseNet は誤差逆伝播のために幅 $c + (i-1)r$ の新たな連結バッファを各層 $i=1,\ldots,n$ で確保するため、$\sum_{i=1}^n (c + (i-1)r) = nc + \frac{n(n-1)}{2}r = \Theta(n^2 r)$ の活性化メモリを要する（例：チャネル数は $10{,}368$ 対 ResNet の $3{,}072$、ただし $n=24, c=64, r=32$）

<!--en:939e954f-->
::: {.slide title="プレアクティベーション ResNet と U-Net のスキップ接続"}

<!--en:274d47c8-->
[変種と拡張]{.kicker}

<!--en:80eceb16-->
- **プレアクティベーション ResNet（He et al., 2016b）：**$\textrm{BN} \to \textrm{ReLU} \to \textrm{Conv}$ を $g(\mathbf{x})$ の内部へ移し、加算後の ReLU を省くことで任意の深さにわたり厳密な単位行列 $\mathbf{I}$ をヤコビ行列に含める

<!--en:c258091b-->
- **ResNet-D ショートカット（He et al., 2019）：**$2 \times 2$ でストライド 2 の平均プーリングをストライド 1 の $1 \times 1$ 畳み込みの前に置き、25% ではなく 100% のピクセルがサンプリングされるようにする

<!--en:207e858a-->
::: {.slide title="理解度チェック：ショートカット、ResNeXt のコスト、DenseNet のメモリ"}

<!--en:26a317d8-->
[理解度チェック]{.kicker}

<!--en:475a3a2c-->
次の 3 つの設計計算を確かめよう

<!--en:2d7fb78f-->
1. **ストライド 2 ショートカットの落とし穴（ResNet-D）：**ストライド 2 の `Residual` ブロックを $24\times 24$ の特徴マップに適用するとき、`conv3` は $1\times 1$ でストライド 2 の畳み込みである。入力の $24\times 24$ の空間位置のうち `conv3` が実際に読み取る割合はどれだけか。また ResNet-D はこれをどう修正するか。

<!--en:25b2759a-->
2. **ResNet-50 対 ResNeXt-50 ブロックの演算量：**$c = 512$ のとき、ResNet-50 のボトルネック（$b = 128, g = 1$）と ResNeXt-50 ブロック（$b = 256, g = 32$）のパラメータ数がほぼ同一であることを確認せよ。

<!--en:24782c56-->
3. **DenseNet のチャネル増加：**密ブロックが $c = 64$ チャネルを受け取り、$n = 4$ 層を成長率 $r = 32$ で実行する。出力チャネル数はいくつになり、4 つの畳み込み全体で合計何個の入力チャネルが読み取られるか。

<!--en:557b98b6-->
**解答：**

<!--en:17dd4b9e-->
1. ストライド 2 の $1\times 1$ カーネルは偶数行・偶数列のみ、すなわち**空間ピクセルの $1/4$（25%）**しかサンプリングせず、残りの $75\%$ を捨てる。ResNet-D はパラメータなしの $2\times 2$ でストライド 2 の平均プーリング層をストライド 1 の $1\times 1$ 畳み込みの前に置き、全ピクセルが寄与するようにする。

<!--en:f2aecbad-->
2. **ResNet-50：**重み数は $2(512)(128) + 9(128^2) = 131{,}072 + 147{,}456 = 278{,}528$。**ResNeXt-50：**重み数は $2(512)(256) + 9(256^2)/32 = 262{,}144 + 18{,}432 = 280{,}576$（差は $<0.8\%$ でボトルネック幅は $2\times$）。

<!--en:c55fdc02-->
3. 出力幅は $64 + 4(32) = 192$ チャネルである。4 つの層は連結された合計 $64 + 96 + 128 + 160 = 448$ 個の入力チャネルを読み取る。

<!--en:3f4e4f9a-->
::: {.slide title="まとめ：残差ネットワークの要点"}

<!--en:d018528e-->
[まとめ]{.kicker}

<!--en:277a8607-->
- **ResNet（$\mathbf{x} + g(\mathbf{x})$）：**恒等写像を $g=0$ に置き（$\mathcal{F} \subseteq \mathcal{F}'$）、$O(n \cdot c)$ の活性化メモリで深いプレーンネットの劣化を解消

<!--en:08978f77-->
- **ResNeXt（$g$ グループ）：**$3 \times 3$ の重みを $9b^2/g$ に削減し、同等の演算量でボトルネック幅 $b$ を 2 倍に拡大

<!--en:7fab2417-->
- **DenseNet（$[\mathbf{x}, f(\mathbf{x})]$）：**成長率 $r$ で特徴を連結するが、素朴な実装では $O(n^2 r)$ の活性化メモリを要する
